# 03 · 下午题（应用技术）专项攻略

> 下午卷 75 分，45 分合格，是"一科不过全盘重来"的高风险科目。它的特点是：**题型固定、模板可背、答案可练**。

## 一、试卷结构

常规设置为 6 道大题，完成 5 道（前 4 道必答，第 5、6 道为 Java / C++ 二选一）：

| 题号 | 题型 | 分值 | 说明 |
| --- | --- | --- | --- |
| 1 | 数据流图 DFD | 15 | 补外部实体、数据存储、数据流、保持父子图平衡 |
| 2 | UML 建模 | 15 | 补类图关系/多重度、用例、顺序图、状态图 |
| 3 | 数据库设计 | 15 | 补 ER 图、转关系模式、写 SQL |
| 4 | 算法设计 | 15 | 补代码、写复杂度、说明算法思想 |
| 5 / 6 | Java / C++ | 15 | 设计模式代码填空 + 设计原则说明 |

**答题时间**：120 分钟，建议每题 20~22 分钟，留 10 分钟检查。

## 二、通用答题纪律

1. **先写编号再写内容**：`(1) 学生、教务管理员`，不要写成一段话。
2. **不留空**：不会的题也要写合理猜测，主观题按点给分，写了才可能得分。
3. **用题目里的术语**：题目叫"加工"就别写"处理"，题目叫"数据存储"就别写"数据库表"。
4. **分点、分行**：一个要点一行，阅卷是按关键词找分。
5. **SQL 写完整**：`SELECT … FROM … WHERE …`，缺关键字直接扣分，末尾分号可写可不写。
6. **关系模式标主外键**：`学生(学号 PK, 姓名)`，不标 PK/FK 通常要扣分。

## 三、DFD（数据流图）

**四要素**：外部实体、加工（处理）、数据存储、数据流。

**解题顺序**

```
1. 先找外部实体：谁在使用系统？谁在给系统提供数据？（人/组织/外部系统）
2. 再定数据存储：系统要长期保存什么？题目里"XX库""XX表""XX档案"都是存储
3. 然后补加工：把"动词"找出来（验证、计算、生成、更新）
4. 最后连数据流：每条流必须有"起点 → 终点"，不能悬空
```

**检查清单**

- [ ] 每个加工都有输入和输出（无"黑洞"、无"奇迹"）
- [ ] 父图与子图的输入流集合一致、输出流集合一致（**平衡**）
- [ ] 外部实体在系统边界外，不与数据存储直接相连
- [ ] 数据流不能双向箭头（要拆成两条）
- [ ] 不出现控制流（"若…则…"不是数据流）

**高频陷阱**

| 陷阱 | 正确做法 |
| --- | --- |
| 把"库存表"当外部实体 | 系统内部维护的数据集合 = 数据存储 |
| 漏掉"费率表""路由表" | 凡系统要查询的静态表都是存储 |
| 父子图不平衡 | 子图不能凭空多出跨边界的流 |

## 四、UML 建模

**常见问法**：补类名、补关系（关联/聚合/组合/泛化）、补多重度、补用例、补顺序图消息、补状态与事件。

**从题干文字到模型的映射**

| 题干措辞 | 模型元素 |
| --- | --- |
| "一个 X 包含多个 Y""X 由 Y 组成，Y 不能独立存在" | 组合，`1 : *` |
| "X 有多个 Y，Y 可以独立存在" | 聚合，`1 : *` |
| "一个 X 对应多个 Y，一个 Y 只属于一个 X" | 关联，`1 : 0..*` |
| "X 是一种 Y" | 泛化（继承） |
| "X 使用 Y 完成某操作" | 依赖 |
| 动词（提交、查询、计算） | 方法（操作） |
| 名词（订单、房间） | 类 |
| 数量词（一个、多个、至少一个） | 多重度 |

**顺序图答题格式**

```
对象：客人、预订界面、预订控制器、房间、预订单
消息：客人→界面:提交预订(房型,日期)
      界面→控制器:创建预订(参数)
      控制器→房间:查询可用(日期)
      ...
```

**状态图**：列出状态 → 找事件 → 标监护条件 → 确认哪些迁移非法（业务约束）。

## 五、数据库设计

**三问套路**

1. **补 ER 图**：找实体（名词）、找联系（动词）、定联系类型（看数量关系）。
2. **转关系模式**：实体→表；`1:n` 把 1 端主键放 n 端；`m:n` 独立成表（主键为组合）。标注 `PK` / `FK`。
3. **写 SQL**：多为"查询满足条件的记录""统计分组""创建视图"。

**SQL 书写模板**

```sql
-- 条件查询 + 连接
SELECT a.列, b.列
FROM 表A a JOIN 表B b ON a.外键 = b.主键
WHERE 条件;

-- 分组统计
SELECT 分组列, COUNT(*) / AVG(列) / SUM(列)
FROM 表
GROUP BY 分组列
HAVING 聚合条件;

-- 不存在/未匹配
SELECT * FROM A WHERE NOT EXISTS (SELECT 1 FROM B WHERE B.外键 = A.主键);

-- 视图
CREATE VIEW 视图名 AS SELECT ...;
```

**踩分点**：`IS NULL` 不能写 `= NULL`；聚合条件用 `HAVING`；`COUNT(*)` 与 `COUNT(列)` 的区别；`ORDER BY` 与 `LIMIT/TOP` 的位置。

## 六、算法设计

**四步法**

1. 读题干说明的算法思想（题目通常已经把思路讲清楚，只是代码有洞）；
2. 定位空格的上下文：空在条件里 → 填比较表达式；空在语句里 → 填赋值或调用；
3. 检查边界：循环起止、数组下标、初始值；
4. 复杂度题：看循环层数与递归深度。

**常考算法与模板**

| 算法 | 关键代码特征 | 复杂度 |
| --- | --- | --- |
| 一次遍历求最大/次大 | `if (a[i] > max1) { max2 = max1; max1 = a[i]; }` | O(n) |
| 二分查找 | `while (low <= high) { mid = (low+high)/2; ... }` | O(log n) |
| 0-1 背包 | `dp[j] = max(dp[j], dp[j-w[i]] + v[i])`，**j 逆序** | O(nC) |
| 最长递增子序列 | `dp[i] = max(dp[j]) + 1 (j < i 且 a[j] < a[i])` | O(n²) |
| 归并排序 | 分治 + 合并辅助数组 | O(n log n) |
| 图遍历 | DFS 递归/栈，BFS 队列 | O(n+e) |

**必答的两句话**

- 逆序原因：**保证每件物品只选一次；正序会变成完全背包**。
- 空间优化：**一维滚动数组把 O(nC) 降到 O(C)**。

## 七、Java / C++ 设计模式题

**答题步骤**

1. 先看类图或题干提到的模式名（常直接给出，如"采用策略模式"）；
2. 看接口/抽象类定义了哪些方法 → 空多半是实现该方法；
3. 看构造方法与成员变量 → 空多半是类型声明或注入；
4. 看调用处 → 空多半是方法名；
5. 设计原则题：写"原则名 + 一句对应说明"。

**高频模式与空位特征**

| 模式 | 常见空位 |
| --- | --- |
| 策略 | 成员类型（接口名）、`strategy.method()`、setter 参数类型 |
| 观察者 | `attach/addObserver`、`for (Observer o : list)`、`update` |
| 模板方法 | 抽象方法名、`public 继承 基类` |
| 单例 | 私有构造、`static` 实例、`getInstance` |
| 工厂方法 | 返回类型、`new 具体类()` |
| 装饰 | 父类引用、`super.method()`、包装调用 |

- [ ] 关系模式标了 PK / FK
- [ ] SQL 有 `SELECT`、`FROM`，条件完整
- [ ] 代码填空的括号、分号没漏
- [ ] 复杂度写了 O( ) 形式
- [ ] 没有留空题
