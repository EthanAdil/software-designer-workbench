## 四、口径与复现

| 项 | 口径 |
| --- | --- |
| 已作答题目 | `answers` 的键数，一题多轮只计 1 题 |
| 作答次数 | 每题 `right + wrong` 累加（同一题多刷按次数累计） |
| 正确率 | 累计 `right / 作答次数`；「本周」用两份快照作差，不是单周独立样本 |
| 新增错题 | `wrong` 新增题号数；「复错」为已有题号 `count` 增长；括号外按题去重、括号内按次数 |
| 未掌握 | `wrong[*].resolved === false` 的条数 |
| 完成任务 | `tasks` 的键数；小时按 `data-plan.js` 中该任务的 `hours` 汇总 |
| 计划投入 | 已打卡任务的**计划小时**，不是实测用时（与「学习计划 → 累计投入」同源） |
| 测评 / 模考 | `exams` 长度，两份快照均为 0 |

**已知局限**：

- 备份只存每题累计次数与最后作答时间，没有逐次时间戳，所以「本周」只能靠两次导出的差值推算，无法按天拆分，也无法区分「首轮正确率」与「回炉后正确率」。
- 打卡记录只有 `{任务id: true}`，没有完成时间，任务归属按计划周计，超前完成的会记在所属周次上（例如 W4 ~ W8 的任务实际在 W2 内完成）。

**复算方式**：读两份 JSON，对 `answers` 逐题作差（题量取键集合差集，作答次数与正确数取差值），`wrong` 取题号与 `count` 差异，`tasks` 取键集合差集，再按 `data-plan.js` 的 `hours` 汇总即得上表数字。
