## 二、密码学基础

### 2.1 算法分类

| 类型 | 算法 | 密钥/输出 | 用途 |
| --- | --- | --- | --- |
| 对称 | DES | 56 位密钥 | 数据加密 |
| 对称 | 3DES | 112/168 位 | 兼容旧系统 |
| 对称 | AES | 128/192/256 位 | 主流对称加密 |
| 对称 | IDEA、RC4 | — | 特定场景 |
| 非对称 | RSA | 1024/2048 位 | 加密、签名、密钥交换 |
| 非对称 | ECC | 较短密钥 | 移动端、资源受限 |
| 非对称 | DSA | — | 仅用于签名 |
| 哈希 | MD5 | 输出 128 位 | 完整性校验（已不推荐） |
| 哈希 | SHA-1 | 输出 160 位 | 完整性校验 |
| 哈希 | SHA-256 | 输出 256 位 | 当前主流 |

**对称与非对称的取舍**：对称加密快、适合大数据量，但密钥分发难；非对称加密慢、适合小数据量（密钥、签名），但解决了密钥分发与不可否认问题。

**混合体制**：用非对称加密传递对称密钥，再用对称密钥加密数据，兼顾效率与安全。TLS/HTTPS 就是这种模式。

### 2.2 哈希函数

- 单向：不可逆，不能"解密"；
- 抗碰撞：不同输入产生相同输出的概率极低；
- 定长输出：无论输入多长，输出长度固定；
- 雪崩效应：输入微小变化导致输出巨大变化。

哈希不是加密算法，不能用于"加密文件内容"，只能做完整性校验、口令存储（加盐）、数字签名摘要。

### 2.3 加密与签名的方向

```
加密传输：发送方用【接收方公钥】加密 → 接收方用【自己私钥】解密
数字签名：发送方用【自己私钥】签名 → 接收方用【发送方公钥】验证
```

数字签名通常先对消息求哈希，再对哈希值签名，原因是：签名运算慢，哈希把任意长度消息压缩成定长摘要，效率更高；同时摘要也能保证完整性。

数字签名保证**完整性 + 不可否认性**，但不保证机密性（签名不隐藏内容）。

### 2.4 数字证书与 PKI

数字证书由 CA 签发，绑定"公钥 + 持有者身份 + 有效期 + CA 签名"，解决公钥真实性、防中间人攻击。

PKI 组成：CA（证书颁发机构）、RA（注册审核）、证书库、CRL（证书吊销列表）、密钥管理。

MAC/HMAC 用共享密钥保证完整性与认证，但不提供不可否认性（双方都能生成）。

## 三、认证与访问控制

### 3.1 身份认证三要素

| 要素 | 例子 |
| --- | --- |
| 所知（something you know） | 口令、PIN |
| 所有（something you have） | 智能卡、U 盾、手机验证码 |
| 所是（something you are） | 指纹、人脸、虹膜 |

双因素认证要求组合两类不同要素，例如"口令 + 短信验证码"。

### 3.2 访问控制模型

| 模型 | 全称 | 特点 | 典型 |
| --- | --- | --- | --- |
| DAC | 自主访问控制 | 资源所有者自主授权 | Unix 文件权限 |
| MAC | 强制访问控制 | 系统按安全标签强制控制 | 军事情报系统、BLP 模型 |
| RBAC | 基于角色的访问控制 | 权限绑定角色，用户分配角色 | 企业管理系统 |

RBAC 的优势是权限管理集中、易审计，人员变动时只需调整角色。

### 3.3 安全协议

| 协议 | 层次 | 作用 |
| --- | --- | --- |
| SSL/TLS | 传输层之上 | 加密 Web 通信，HTTPS 的基础 |
| IPSec | 网络层 | AH 提供完整性认证，ESP 提供加密与认证 |
| SSH | 应用层 | 加密远程登录 |
| WPA2 | 链路层 | 无线局域网加密 |

## 四、网络攻击与防护

### 4.1 攻击类型

| 攻击 | 原理 | 防护 |
| --- | --- | --- |
| DDoS | 大量傀儡机耗尽目标资源 | 流量清洗、限流、CDN |
| ARP 欺骗 | 伪造 IP-MAC 映射，截获流量 | 静态 ARP、ARP 防护 |
| DNS 劫持 | 篡改解析结果 | DNSSEC、可信 DNS |
| SQL 注入 | 输入拼接进 SQL 语句 | 参数化查询、输入校验 |
| XSS | 注入恶意脚本到页面 | 输出转义、CSP |
| CSRF | 冒用已认证会话发起请求 | CSRF Token、SameSite |
| 重放攻击 | 截获报文后重复发送 | 时间戳、随机数、序列号 |
| 暴力破解 | 穷举口令 | 强口令、锁定、验证码 |
| 社会工程 | 欺骗人获取信息 | 安全意识培训 |

被动攻击（窃听、流量分析）难检测，防护重于检测；主动攻击（篡改、伪造、重放、拒绝服务）可检测但难预防。

### 4.2 防护设备

| 设备 | 层次 | 特点 |
| --- | --- | --- |
| 包过滤防火墙 | 网络层 | 检查源/目的 IP、端口，快但粗 |
| 应用代理防火墙 | 应用层 | 解析应用协议内容，细但慢 |
| 状态检测防火墙 | 传输层/网络层 | 跟踪连接状态，兼顾效率与安全 |
| IDS | — | 被动检测、告警，不阻断 |
| IPS | — | 主动检测并阻断 |
| 蜜罐 | — | 诱捕攻击者、收集情报 |
| WAF | 应用层 | 专门防护 Web 攻击 |

VPN：IPSec VPN 在网络层，适合站点互联；SSL VPN 在应用层，浏览器即可接入，适合远程办公。

### 4.3 恶意代码

| 类型 | 特征 |
| --- | --- |
| 病毒 | 寄生在宿主程序中，需用户触发 |
| 蠕虫 | 可独立运行、自主通过网络传播 |
| 木马 | 伪装正常程序，提供远程控制后门 |
| 逻辑炸弹 | 满足特定条件时触发破坏 |
| 勒索软件 | 加密文件索要赎金 |

## 五、安全体系与管理

**信息安全五要素**：机密性、完整性、可用性、可控性、不可否认性。

**等级保护五级**：一级自主保护、二级指导保护、三级监督保护、四级强制保护、五级专控保护。金融、电力、政务等关键行业通常要求三级及以上。

**风险评估**：资产识别 → 威胁识别 → 脆弱性识别 → 风险计算（可能性 × 影响）→ 风险处置（规避/转移/减轻/接受）。

**安全管理**：制定策略 → 实施控制 → 运行监控 → 审计改进，技术与管理并重。

## 六、标准化

### 6.1 标准层级

| 层级 | 代号 | 说明 |
| --- | --- | --- |
| 国际标准 | ISO、IEC、ITU | 国际组织发布 |

## 七、知识产权

### 7.1 著作权（版权）

- **自动产生**：作品创作完成之日起自动享有，无需登记；软件著作权登记是自愿的，用于举证与交易。
- 保护对象：软件的程序及其文档；不保护思想、算法、处理过程、操作方法、数学概念。
- 保护期：

| 权利 | 保护期 |
| --- | --- |
| 署名权、修改权、保护作品完整权 | 永久 |
| 发表权、财产权（自然人） | 作者终生 + 死后 50 年 |
| 法人作品 | 首次发表后 50 年 |

- 归属规则：

| 场景 | 归属 |
| --- | --- |
| 委托开发，合同有约定 | 按约定 |
| 委托开发，**无约定** | **受托方（开发者）** |
| 职务作品（一般） | 作者，单位有两年优先使用权 |
| 职务作品（主要利用单位物质技术条件、单位担责） | 作者仅署名权，其余归单位 |

### 7.2 专利

| 类型 | 保护期 | 保护对象 |
| --- | --- | --- |
| 发明专利 | 20 年 | 产品、方法或其改进 |
| 实用新型 | 10 年 | 产品的形状、构造 |
| 外观设计 | 15 年 | 产品的外观形状、图案、色彩 |

均自**申请日**起算。专利三性：新颖性、创造性、实用性。

**职务发明**：执行本单位任务或主要利用本单位物质技术条件完成的发明创造，申请专利的权利属于单位；非职务发明归发明人。

### 7.3 商标与商业秘密

- 商标注册有效期 10 年，期满前 12 个月内办理续展，可无限续展；
- 商标注册遵循申请在先原则，同一天申请的使用在先者优先；
- 商业秘密：不为公众所知悉、具有商业价值、采取保密措施，无期限但需自行举证。

### 7.4 侵权与合理使用

侵权形式：未经许可复制、发行、改编、翻译、信息网络传播；软件领域常见非法复制、超许可数量安装、反编译（超出合法范围）。

**合理使用**（可不经许可、不付报酬，但需指明作者与作品名称）：个人学习研究欣赏、新闻报道、教学科研少量复制、免费表演、国家机关执行公务等。

**归责原则**：以过错责任为主；销售侵权复制品能证明合法来源的，可免除赔偿责任。

## 九、易错辨析

| 错误认知 | 正确结论 | 原因 |
| --- | --- | --- |
| 数字签名用接收方公钥 | 签名用发送方私钥 | 私钥唯一对应签名者身份 |
| 哈希可以解密 | 哈希不可逆 | 它是单向摘要，不是加密 |
| 对称加密可以实现不可否认 | 不能 | 双方共享密钥，无法证明是谁发的 |
| 委托开发无约定归委托方 | 归受托方（开发者） | 法律默认保护创作者 |
| 外观设计保护期 10 年 | 2021 年修法后为 15 年 | 旧题可能仍写 10 年 |
| 著作权需登记才受保护 | 创作完成即自动产生 | 登记只用于举证 |
| IDS 可以主动阻断 | IDS 只告警，IPS 才阻断 | 两者定位不同 |
| MAC 只表示强制访问控制 | 也可表示消息认证码，需看上下文 | 同一缩写在安全领域有两种含义 |
| 商业秘密有固定保护期 | 无期限，但需保密措施 | 公开即失去保护 |

> 答案与解析：
> 1) 发送方私钥签名，发送方公钥验证。
> 2) READ COMMITTED。
> 3) 受托方（开发者）。
> 4) 15 年（自申请日）。
> 5) 蠕虫可独立运行并自主传播，病毒需寄生宿主、通常需用户触发。
> 6) RSA 是非对称加密算法；DSA 仅用于签名，不能加密。
> 7) 签名运算慢，哈希把任意长度消息压缩为定长摘要，提高效率；摘要同时保证完整性。
> 8) DAC 由资源所有者自主授权；MAC 由系统按安全标签强制控制；RBAC 权限绑定角色、用户分配角色。
> 9) 期满前 12 个月内办理续展，可无限次续展。
> 10) 保护程序及其文档；不保护思想、算法、处理过程、操作方法和数学概念。
