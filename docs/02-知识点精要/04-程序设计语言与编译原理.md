# 04 · 程序设计语言与编译原理（上午 5 题）

## 一、编译过程五阶段

| 阶段 | 输入 | 输出 | 用到的理论 | 典型任务 |
| --- | --- | --- | --- | --- |
| 词法分析 | 源程序字符流 | token 序列 | 正规式 / 有限自动机 | 识别标识符、常数、关键字 |
| 语法分析 | token 序列 | 语法树 | 上下文无关文法 | 检查结构是否符合文法 |
| 语义分析 | 语法树 | 带语义信息的中间表示 | 属性文法 | 类型检查、变量是否声明 |
| 中间代码生成与优化 | 中间表示 | 优化的中间代码 | — | 四元式、常量合并、循环优化 |
| 目标代码生成 | 中间代码 | 目标机器代码 | — | 寄存器分配、指令选择 |

> **最常考的一句话**："变量是否已声明"属于**语义分析**，不是语法分析。

编译 vs 解释：编译先整体翻译再执行（快、跨平台差）；解释逐句翻译执行（慢、跨平台好）。

## 二、文法与自动机

```
0 型 短语文法  >  1 型 上下文有关  >  2 型 上下文无关  >  3 型 正规文法
                                    ↑ 程序语言语法         ↑ 词法（正规式）
```

| 概念 | 关键点 |
| --- | --- |
| DFA | 每个状态对每个输入**至多一条**出边，无 ε 转移 |
| NFA | 允许多条出边与 ε 转移 |
| 两者关系 | 识别能力等价，都可识别正规集；NFA 可用子集构造法转 DFA |
| 正规式 | 描述词法规则，如 `(a\|b)*abb` 表示"以 abb 结尾的 a、b 串" |
| 二义性文法 | 同一个句子存在两棵不同语法树 |

## 三、表达式转换（每年必考）

**中缀 → 后缀**

1. 遇操作数直接输出；
2. 遇运算符：弹出栈中优先级 ≥ 当前的全部运算符，再入栈；
3. 遇 `(` 直接入栈，遇 `)` 弹栈直到 `(`；
4. 扫描结束，弹出栈中剩余运算符。

```
a + b * (c - d)   →   a b c d - * +
(a + b) * c       →   a b + c *
```

**后缀求值**：遇操作数入栈；遇运算符弹出两个（先出的是右操作数）运算后入栈。

`3 4 + 5 *` → (3+4)=7 → 7×5 = **35**

## 四、程序语言基础

| 概念 | 说明 |
| --- | --- |
| 传值 | 形参是实参副本，函数内修改不影响实参（C 默认） |
| 传地址/引用 | 形参与实参同一存储，修改生效 |
| 传名 | 宏展开式替换，可能重复求值 |
| 静态类型 | 编译期检查（C/Java/C++） |
| 动态类型 | 运行期检查（Python/JS/Ruby） |
| 语言范型 | 命令式（C）、面向对象（Java）、函数式（Lisp）、逻辑式（Prolog） |

## 五、中间代码与优化

- 中间代码形式：四元式 `(运算符, 操作数1, 操作数2, 结果)`、三元式、逆波兰式、树。
- 局部优化：基本块内的常量合并、公共子表达式删除、死代码消除。
- 循环优化：循环不变式外提、强度削弱（乘法换加法）、循环展开。

## 六、自检题

1. 词法分析用什么理论？语法分析用什么文法？
2. `a*(b+c)-d` 的后缀表达式是什么？
3. DFA 与 NFA 的本质区别是什么？
4. "数组下标越界检查"属于哪个阶段？
5. 编译方式与解释方式各自的优缺点？

> 答案速查：1) 正规式/有限自动机，上下文无关文法（2 型）；2) `abc+*d-`；3) DFA 每个状态对每个输入至多一条转移且无 ε 边；4) 语义分析（运行期检查则属目标代码/运行时，考试通常按语义分析答）；5) 编译快但需重新编译、跨平台差；解释灵活但慢。
