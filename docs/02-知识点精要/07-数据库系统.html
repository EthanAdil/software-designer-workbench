二、数据库体系结构

2.1 三级模式

模式别名描述数量
外模式子模式/用户模式用户看到的数据视图多个
模式概念模式/逻辑模式全体数据的逻辑结构一个
内模式存储模式物理存储结构一个

2.2 两级映像与独立性

映像保证含义
外模式/模式逻辑独立性逻辑结构改变，用户视图与应用程序不变
模式/内模式物理独立性存储结构改变，逻辑结构不变

记忆：外-逻、内-物——外模式对应逻辑独立性，内模式对应物理独立性。

2.3 数据模型与 DBMS

数据模型三要素：数据结构（描述对象与联系）、数据操作（增删改查）、完整性约束（实体/参照/用户定义）。

DBMS 主要功能：数据定义、数据操纵、数据库运行管理（并发、恢复、完整性）、数据库建立与维护、数据字典。

三、ER 模型与关系转换

3.1 ER 三要素

  • 实体：矩形；属性：椭圆；联系：菱形。
  • 联系类型：1:1、1:n、m:n。
  • 弱实体：双线矩形，依赖强实体的主键存在，不能独立存在。
  • 多值属性：双线椭圆，转换时单独成表。
  • 派生属性：虚线椭圆，可由其他属性计算，不存储。

3.2 转换规则

联系类型转换方式说明
1:1可合并到任一端把另一端主键作为外键，加入唯一约束
1:n把 1 端主键放入 n 端作外键n 端是"多"的一方
m:n必须独立建表主键为两端主键的组合，联系属性放入该表

例：教师与课程之间是 m:n 的"讲授"联系，带"课时"属性。
转换为：教师（教师号，姓名）、课程（课程号，课程名）、讲授（教师号，课程号，课时），主键为（教师号，课程号），两个外键分别引用教师与课程。

判断技巧：看"一个 X 能对应几个 Y"——两边都是多，就独立建表；一边是多，就把"一"端主键塞到"多"端。

冲突类型例子

命名冲突同名异义、异名同义

四、关系代数与规范化

4.1 关系代数

运算符号含义SQL 对应
选择σ按条件取行WHERE
投影π取列并去重SELECT DISTINCT
连接⋈按条件合并两表JOIN

并/差/交∪ / − / ∩集合运算UNION / EXCEPT / INTERSECT

除运算：R(A,B) ÷ S(B) 得到"在 R 中与 S 中所有 B 值都有关的 A 值"。例：选课(学号,课程号) ÷ 课程(课程号) = 选修了全部课程的学生。考试若考"没有选修某课的学生"，用差集或 NOT EXISTS。

4.2 函数依赖

  • 完全函数依赖：X→Y，且 X 的任何真子集都不能决定 Y；
  • 部分函数依赖：X 的某个真子集就能决定 Y；
  • 传递函数依赖：X→Y, Y→Z 且 Y 不决定 X，则 X 传递决定 Z。

4.3 候选键求解（闭包法）

属性集 X 的闭包 X+：从 X 出发，反复用函数依赖扩展，直到不再增加。

求候选键步骤：

  1. 找出只出现在依赖左边、从不出现在右边的属性，必属于候选键；
  2. 从这些属性出发求闭包；
  3. 若闭包包含全部属性，则为候选键；否则尝试加入其他属性，直到闭包完整；
  4. 去掉冗余属性，得到最小候选键。

例：R(A,B,C)，F={A→B, B→C}。

  • A+ = ABC（A→B，B→C），故 A 是候选键；
  • B+ = BC，不含 A；C+ = C；AB+ = ABC 但 A 已足够，故候选键只有 A。

4.4 范式判定

范式要求消除的问题
1NF属性不可再分非原子属性
2NF1NF + 消除非主属性对码的部分依赖部分依赖
3NF2NF + 消除非主属性对码的传递依赖传递依赖
BCNF每个非平凡函数依赖的决定因素都是候选键主属性对码的依赖

判定顺序：先找候选键 → 看是否有非主属性对码的部分依赖（2NF）→ 看是否有传递依赖（3NF）→ 看每个决定因素是否都是候选键（BCNF）。

例：R(A,B,C)，F={A→B, B→C}，候选键 A。

  • A→B 是完全依赖，B→C 是传递依赖（A→B→C），所以 R 满足 2NF 但不满足 3NF。
  • 分解为 R1(A,B)、R2(B,C)：R1 的键是 A、R2 的键是 B，都满足 3NF 与 BCNF。

4.5 无损连接与保持依赖

无损连接判定（分解为两个关系时）：R1 ∩ R2 → R1 - R2 或 R1 ∩ R2 → R2 - R1 成立。

上例：R1∩R2 = B，R1-R2 = A，R2-R1 = C。B→C 成立，故无损。

保持函数依赖：分解后各关系的函数依赖并集，能推出原关系 F 中的每个依赖。无损连接与保持依赖是两个独立目标，有时不能同时满足（3NF 分解可同时满足，BCNF 分解不一定保持依赖）。

最小函数依赖集三步：右边单属性化 → 去掉冗余依赖 → 去掉左边冗余属性。

五、SQL

5.1 分类

类别语句

DCLGRANT / REVOKE
事务控制COMMIT / ROLLBACK / SAVEPOINT

5.2 执行顺序与连接

FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
  • WHERE 作用于分组前，HAVING 作用于分组后，聚合条件必须写在 HAVING；
  • INNER JOIN 只保留匹配行；LEFT JOIN 保留左表全部行，右表无匹配填 NULL；RIGHT JOIN 反之；
  • 子查询：IN 适合非相关子查询，EXISTS 适合相关子查询（外层每行执行一次）。

5.3 经典写法

-- 每门课平均分 > 80，按平均分降序
SELECT 课程号, AVG(成绩) AS 平均分
FROM 选课
GROUP BY 课程号
HAVING AVG(成绩) > 80
ORDER BY 平均分 DESC;

-- 没被选修的课程
SELECT 课程号, 课程名
FROM 课程
WHERE 课程号 NOT IN (SELECT 课程号 FROM 选课);

-- 尚未归还的借阅记录（多表连接）
SELECT 读者.姓名, 图书.书名, 借阅.借阅日期
FROM 借阅
JOIN 读者 ON 借阅.读者号 = 读者.读者号
JOIN 图书 ON 借阅.书号 = 图书.书号
WHERE 借阅.归还日期 IS NULL;

-- 借阅次数不少于 3 次的读者
SELECT 读者号, COUNT(*) AS 借阅次数
FROM 借阅
GROUP BY 读者号
HAVING COUNT(*) >= 3;

-- 前 3 名（MySQL 写法）
SELECT 工号, SUM(工时) AS 总工时
FROM 参与
GROUP BY 工号
ORDER BY 总工时 DESC
LIMIT 3;

-- 授权
GRANT SELECT, UPDATE ON 选课 TO 教务员;

5.4 视图、索引与约束

  • 视图：虚表，不存数据（物化视图除外），用于简化查询与权限控制；含聚合、DISTINCT、GROUP BY 的视图通常不可更新。
  • 索引：加快查询、减慢增删改；聚簇索引决定物理顺序，一张表只能有一个；非聚簇索引需回表。
  • 约束：PRIMARY KEY（非空唯一）、FOREIGN KEY（参照完整性）、UNIQUE、CHECK、NOT NULL。

六、事务与并发

6.1 ACID

特性含义保障手段
原子性 A事务要么全做、要么全不做日志 UNDO
一致性 C事务前后数据库都处于一致状态完整性约束 + 应用逻辑
隔离性 I并发事务互不干扰锁、MVCC
持久性 D提交后永久保存日志 REDO

6.2 并发问题与隔离级别

问题含义
丢失更新两个事务同时读同一数据，后写覆盖先写
读脏数据读到另一个事务未提交的数据
不可重复读同一事务两次读同一行，结果不同（被修改）
幻读同一事务两次查询，结果集行数不同（被插入/删除）
隔离级别脏读不可重复读幻读
READ UNCOMMITTED可能可能可能
READ COMMITTED不会可能可能
REPEATABLE READ不会不会可能
SERIALIZABLE不会不会不会

记忆：级别越高，一致性越强、并发越低。避免脏读至少 READ COMMITTED，避免幻读必须 SERIALIZABLE。

6.3 封锁与两段锁

  • 共享锁 S（读锁）：多个事务可同时持有；
  • 排他锁 X（写锁）：与任何锁互斥。

两段锁协议（2PL）：扩展阶段只能加锁、不能解锁；收缩阶段只能解锁、不能加锁。遵守 2PL 的调度一定可串行化，但可能死锁。

死锁预防：一次封锁法（一次性申请全部锁）、顺序封锁法（按固定顺序申请）。死锁检测：事务依赖图，出现环即死锁。

七、备份与恢复

分类类型特点
按状态静态转储（冷备）停机、一致性好
按状态动态转储（热备）不停机、需日志配合
按范围海量转储全量备份
按范围增量转储只备份上次备份后变化的数据

日志恢复：

  • UNDO：撤销未提交的事务（原子性）；
  • REDO：重做已提交但尚未写回磁盘的事务（持久性）；
  • 检查点：定期把内存中的脏页刷盘并记录检查点，恢复时只需从检查点开始扫描，减少恢复时间。

故障类型：事务故障（回滚该事务）、系统故障（重启，UNDO 未提交 + REDO 已提交）、介质故障（用备份 + 日志恢复）。

十、自检题

  3. m:n 联系转关系模式时主键怎么定？（对应题库 DB-048）
  4. 哪种隔离级别能避免幻读？（对应题库 DB-031）
  5. 两段锁协议能保证什么，不能避免什么？（对应题库 DB-013）

  7. 选课(学号,课程号) ÷ 课程(课程号) 的语义是什么？（对应题库 DB-023）
  8. 查询"平均分大于 80 的课程号及平均分"怎么写？（对应题库 DB-028）
  9. UNDO 与 REDO 分别恢复什么？（对应题库 DB-044）
  10. 静态转储与动态转储的区别？（对应题库 DB-033）

答案与解析：
1) 外模式/模式映像。
2) 候选键 A；满足 2NF，不满足 3NF（存在 A→B→C 传递依赖）。
3) 两端主键的组合，联系属性一并放入。
4) SERIALIZABLE。
5) 保证调度可串行化；不能避免死锁。
6) R1∩R2 → R1-R2 或 R1∩R2 → R2-R1 成立。
7) 选修了全部课程的学生。
8) SELECT 课程号, AVG(成绩) FROM 选课 GROUP BY 课程号 HAVING AVG(成绩) > 80;
9) UNDO 撤销未提交事务；REDO 重做已提交但未写盘的事务。
10) 静态转储需停机、一致性好；动态转储不停机、需日志配合。
