二、面向对象基础

2.1 四大特性

特性含义作用
封装隐藏内部实现，只暴露接口降低耦合、保护数据
继承子类复用父类的属性与方法复用与扩展
多态同一消息被不同对象接收产生不同行为提高扩展性
抽象提取共性，忽略细节简化问题

多态的两种形态：

  • 编译期多态（静态绑定）：重载，编译时根据参数类型/个数决定调用哪个方法；
  • 运行期多态（动态绑定）：重写/虚函数，运行时根据对象实际类型决定调用哪个实现。

2.2 重载与重写

对比重载 overload重写 override
发生位置同一个类中子类与父类之间
方法名相同相同
参数列表必须不同必须相同
返回值可不同相同或协变
绑定时机编译期运行期
访问权限无限制不能比父类更严格

2.3 SOLID 五原则

原则含义反例
单一职责 SRP一个类只负责一件事一个类既管订单又管发邮件
开闭 OCP对扩展开放、对修改关闭每加一种折扣就改 if-else
里氏替换 LSP子类可替换父类且不破坏语义正方形继承长方形导致面积错误
接口隔离 ISP不强迫依赖无用接口胖接口让实现类空实现一堆方法
依赖倒置 DIP依赖抽象而非具体实现业务层直接 new 具体数据库驱动

抽象类与接口：抽象类可有属性与部分实现，表示"是什么"；接口只声明行为，表示"能做什么"。Java 类单继承、接口多实现。

三、UML 图

3.1 图分类

类别图用途
结构图类图类、属性、方法、关系
结构图对象图某一时刻的对象快照
结构图包图组织与依赖
结构图构件图物理组件与接口
结构图部署图节点与部署
结构图组合结构图类内部的组合结构
行为图用例图参与者与系统功能
行为图活动图业务流程/算法，支持并发与泳道
行为图状态图单个对象生命周期
行为图顺序图消息的时间顺序
行为图通信图对象链接关系（消息编号表顺序）
行为图定时图状态随时间变化
行为图交互概览图多个交互的组合

考试常问"描述对象生命周期用哪种图"→ 状态图；"强调消息时间顺序"→ 顺序图；"强调对象链接关系"→ 通信图；"部署节点"→ 部署图。

3.2 类图六种关系

关系图形语义代码体现
依赖虚线 + 开口箭头临时使用方法参数、局部变量
关联实线（可带箭头）长期结构关系成员变量
聚合空心菱形（菱形在整体端）整体-部分，可分离成员对象，外部创建
组合实心菱形（菱形在整体端）整体-部分，同生共死成员对象，内部创建
泛化实线 + 空心三角（指向父类）继承extends
实现虚线 + 空心三角（指向接口）实现接口implements

强弱顺序：依赖 < 关联 < 聚合 < 组合 < 泛化/实现（后两者是继承关系，不是组合强弱）。

多重度：1（恰好一个）、0..1（零或一个）、*（零或多个）、1..*（至少一个）、m..n。

例："一个读者可以借多本书，一本书同一时刻只能被一个读者借" → 读者端 1，图书端 0..*（历史借阅）或 0..1（当前借阅），要看题目语义。

3.3 用例图

  • 参与者：人或其他系统，用小人表示；
  • 用例：椭圆，表示一个完整功能；
  • include：必然发生的公共行为，箭头指向被包含用例（如"下单"include"登录校验"）；
  • extend：可选/条件触发的扩展，箭头指向基础用例（如"支付"extend"使用优惠券"）；
  • 泛化：参与者之间、用例之间的继承。

3.4 顺序图与状态图

顺序图：对象横向排列，生命线向下延伸，消息箭头表示调用，激活条表示对象正在执行。同步消息实心箭头、异步消息开口箭头、返回消息虚线箭头。组合片段 alt（分支）、loop（循环）、opt（可选）。

状态图：圆角矩形表示状态，实心圆表示初态，同心圆表示终态；迁移箭头标注"事件 [监护条件] / 动作"。

活动图：圆角矩形表示活动，菱形表示判定，粗横线表示并发分叉/汇合，泳道表示责任划分。

4.5 易混辨析

对比区别
适配器 vs 桥接适配器事后补救（已有类接口不合）；桥接事前设计（抽象与实现分离）
策略 vs 状态策略由客户端选算法；状态由对象内部迁移驱动
装饰 vs 代理装饰叠加职责；代理控制访问（远程/延迟/权限）
工厂方法 vs 抽象工厂前者一类产品；后者一系列产品族
组合 vs 聚合菱形都在整体端，实心才是强拥有
重载 vs 重写重载同类同名不同参（编译期）；重写子类覆盖父类同名同参（运行期）
外观 vs 中介者外观简化单向调用；中介者协调多向交互

五、面向对象分析与设计

  • OOA（分析）：从问题域识别对象、属性、服务与关系，建立类图/用例图，不涉及具体实现。
  • OOD（设计）：在分析模型基础上补充接口、抽象类、设计模式、数据库映射等实现细节。
  • 领域模型：描述问题域概念（如"订单""客户"），不含技术细节；
  • 设计模型：描述实现结构（如"OrderDAO""PaymentService"），含技术决策。

OOA/OOD 都强调：高内聚低耦合、依赖抽象、单一职责、用例驱动、迭代增量。

八、自检题

  1. 组合与聚合的图形区别在哪一端？（对应题库 OO-003）
  2. 希望"动态给对象加功能"，选什么模式？（对应题库 OO-012）
  3. 一个系统要支持多种数据库驱动切换，用什么模式？（对应题库 OO-014）
  4. include 与 extend 的使用场景区别？（对应题库 OO-049）
  5. 单例模式的关键实现要点？（对应题库 OO-008）
  6. 顺序图与通信图各自的侧重点是什么？（对应题库 OO-029）
  7. "多级审批、逐级处理"适合什么模式？（对应题库 OO-038）
  8. 抽象工厂与工厂方法的核心区别？（对应题库 OO-010）
  9. 状态图适合描述什么？活动图的并发如何表示？（对应题库 OO-006 / OO-007）
  10. 依赖倒置原则的含义是什么？（对应题库 OO-023）

答案与解析：
1) 菱形都画在"整体"一端，实心为组合、空心为聚合。
2) 装饰模式。
3) 桥接（抽象与实现分离）或策略（算法可替换），看是否需要整体替换实现；答桥接更稳。
4) include 是必然包含的公共行为；extend 是条件/可选扩展。
5) 私有构造 + 静态私有实例 + 静态公共获取方法；并发下用双检锁或静态内部类。
6) 顺序图强调消息的时间顺序；通信图强调对象之间的链接关系。
7) 职责链模式。
8) 工厂方法创建一类产品；抽象工厂创建一系列相关产品（产品族）。
9) 状态图描述单个对象在生命周期内的状态与迁移；活动图用同步条（粗横线）表示并发分叉与汇合。
10) 高层模块与低层模块都依赖抽象，抽象不依赖细节，细节依赖抽象。
