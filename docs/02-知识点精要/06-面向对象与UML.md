# 06 · 面向对象与 UML（上午 9 题 + 下午 2 题）

## 一、类图五种关系

| 关系 | 图形 | 语义 | 代码体现 |
| --- | --- | --- | --- |
| 依赖 | 虚线 + 开口箭头 | 临时使用 | 方法参数、局部变量 |
| 关联 | 实线（可带箭头） | 长期结构关系 | 成员变量 |
| 聚合 | 空心菱形（菱形在整体端） | 整体-部分，可分离 | 成员对象，外部创建 |
| 组合 | 实心菱形（菱形在整体端） | 整体-部分，同生共死 | 成员对象，内部创建 |
| 泛化 | 实线 + 空心三角（指向父类） | 继承 | `extends` |
| 实现 | 虚线 + 空心三角（指向接口） | 实现接口 | `implements` |

**多重度**：`1`、`0..1`、`*`、`1..*`。

**用例关系**：`include` 必然包含的公共行为；`extend` 条件触发的扩展；泛化。

## 三、设计模式 23 种

**创建型（5）**

| 模式 | 一句话意图 |
| --- | --- |
| 单例 Singleton | 保证唯一实例 + 全局访问点 |
| 工厂方法 Factory Method | 定义创建接口，子类决定实例化哪个类 |
| 抽象工厂 Abstract Factory | 创建一系列相关对象（多产品族） |
| 建造者 Builder | 分步构建复杂对象，构建与表示分离 |
| 原型 Prototype | 通过克隆已有对象创建新对象 |

**结构型（7）**

| 模式 | 一句话意图 |
| --- | --- |
| 适配器 Adapter | 接口转换，让不兼容的类协同 |
| 桥接 Bridge | 抽象与实现分离，各自独立变化 |
| 组合 Composite | 树形结构表示整体-部分，统一对待 |
| 装饰 Decorator | 动态给对象添加职责 |
| 外观 Facade | 为子系统提供统一的高层接口 |
| 享元 Flyweight | 共享细粒度对象，节省内存 |
| 代理 Proxy | 控制对对象的访问 |

**行为型（11）**

| 模式 | 一句话意图 |
| --- | --- |
| 职责链 Chain of Responsibility | 请求沿链传递，直到被处理 |
| 命令 Command | 把请求封装为对象，支持撤销/排队 |
| 解释器 Interpreter | 给定语言定义文法并解释句子 |
| 迭代器 Iterator | 顺序访问聚合元素而不暴露内部 |
| 中介者 Mediator | 集中处理对象间的复杂交互 |
| 备忘录 Memento | 捕获并恢复对象内部状态 |
| 观察者 Observer | 一对多依赖，状态变化自动通知 |
| 状态 State | 状态改变时行为随之改变 |
| 策略 Strategy | 算法族可互换，客户端选择 |
| 模板方法 Template Method | 父类定骨架，子类实现步骤 |
| 访问者 Visitor | 在不改变元素类的前提下增加操作 |

## 四、易混辨析（高频）

| 对比 | 区别 |
| --- | --- |
| 适配器 vs 桥接 | 适配器事后补救（已有类接口不合）；桥接事前设计（抽象与实现分离） |
| 策略 vs 状态 | 策略由客户端选算法；状态由对象内部迁移驱动 |
| 装饰 vs 代理 | 装饰叠加职责；代理控制访问（远程/延迟/权限） |
| 工厂方法 vs 抽象工厂 | 前者一类产品；后者一系列产品族 |
| 聚合 vs 组合 | 菱形都在整体端，实心才是强拥有 |
| 重载 vs 重写 | 重载同类同名不同参（编译期）；重写子类覆盖父类同名同参（运行期） |

## 五、面向对象设计原则

| 原则 | 含义 |
| --- | --- |
| 单一职责 SRP | 一个类只负责一件事 |
| 开闭 OCP | 对扩展开放，对修改关闭 |
| 里氏替换 LSP | 子类可替换父类且不破坏语义 |
| 接口隔离 ISP | 不强迫依赖无用接口 |
| 依赖倒置 DIP | 依赖抽象而非具体实现 |

## 六、自检题

1. 组合与聚合的图形区别在哪一端？
2. 希望"动态给对象加功能"，选什么模式？
3. 一个系统要支持多种数据库驱动切换，用什么模式？
4. `include` 与 `extend` 的使用场景区别？
5. 单例模式的关键实现要点？

> 答案速查：1) 菱形都画在"整体"一端，实心为组合；2) 装饰模式；3) 策略/工厂方法/桥接均可，视"是否需整体替换实现"答桥接或策略；4) include 是必然包含的公共行为，extend 是条件/可选扩展；5) 私有构造 + 静态私有实例 + 静态公共获取方法（并发下需双检锁或静态内部类）。
