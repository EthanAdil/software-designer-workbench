## 二、面向对象基础

### 2.1 四大特性

| 特性 | 含义 | 作用 |
| --- | --- | --- |
| 封装 | 隐藏内部实现，只暴露接口 | 降低耦合、保护数据 |
| 继承 | 子类复用父类的属性与方法 | 复用与扩展 |
| 多态 | 同一消息被不同对象接收产生不同行为 | 提高扩展性 |
| 抽象 | 提取共性，忽略细节 | 简化问题 |

**多态的两种形态**：

- 编译期多态（静态绑定）：重载，编译时根据参数类型/个数决定调用哪个方法；
- 运行期多态（动态绑定）：重写/虚函数，运行时根据对象实际类型决定调用哪个实现。

### 2.2 重载与重写

| 对比 | 重载 overload | 重写 override |
| --- | --- | --- |
| 发生位置 | 同一个类中 | 子类与父类之间 |
| 方法名 | 相同 | 相同 |
| 参数列表 | 必须不同 | 必须相同 |
| 返回值 | 可不同 | 相同或协变 |
| 绑定时机 | 编译期 | 运行期 |
| 访问权限 | 无限制 | 不能比父类更严格 |

### 2.3 SOLID 五原则

| 原则 | 含义 | 反例 |
| --- | --- | --- |
| 单一职责 SRP | 一个类只负责一件事 | 一个类既管订单又管发邮件 |
| 开闭 OCP | 对扩展开放、对修改关闭 | 每加一种折扣就改 if-else |
| 里氏替换 LSP | 子类可替换父类且不破坏语义 | 正方形继承长方形导致面积错误 |
| 接口隔离 ISP | 不强迫依赖无用接口 | 胖接口让实现类空实现一堆方法 |
| 依赖倒置 DIP | 依赖抽象而非具体实现 | 业务层直接 new 具体数据库驱动 |

**抽象类与接口**：抽象类可有属性与部分实现，表示"是什么"；接口只声明行为，表示"能做什么"。Java 类单继承、接口多实现。

## 三、UML 图

### 3.1 图分类

| 类别 | 图 | 用途 |
| --- | --- | --- |
| 结构图 | 类图 | 类、属性、方法、关系 |
| 结构图 | 对象图 | 某一时刻的对象快照 |
| 结构图 | 包图 | 组织与依赖 |
| 结构图 | 构件图 | 物理组件与接口 |
| 结构图 | 部署图 | 节点与部署 |
| 结构图 | 组合结构图 | 类内部的组合结构 |
| 行为图 | 用例图 | 参与者与系统功能 |
| 行为图 | 活动图 | 业务流程/算法，支持并发与泳道 |
| 行为图 | 状态图 | 单个对象生命周期 |
| 行为图 | 顺序图 | 消息的时间顺序 |
| 行为图 | 通信图 | 对象链接关系（消息编号表顺序） |
| 行为图 | 定时图 | 状态随时间变化 |
| 行为图 | 交互概览图 | 多个交互的组合 |

考试常问"描述对象生命周期用哪种图"→ 状态图；"强调消息时间顺序"→ 顺序图；"强调对象链接关系"→ 通信图；"部署节点"→ 部署图。

### 3.2 类图六种关系

| 关系 | 图形 | 语义 | 代码体现 |
| --- | --- | --- | --- |
| 依赖 | 虚线 + 开口箭头 | 临时使用 | 方法参数、局部变量 |
| 关联 | 实线（可带箭头） | 长期结构关系 | 成员变量 |
| 聚合 | 空心菱形（菱形在整体端） | 整体-部分，可分离 | 成员对象，外部创建 |
| 组合 | 实心菱形（菱形在整体端） | 整体-部分，同生共死 | 成员对象，内部创建 |
| 泛化 | 实线 + 空心三角（指向父类） | 继承 | `extends` |
| 实现 | 虚线 + 空心三角（指向接口） | 实现接口 | `implements` |

强弱顺序：依赖 < 关联 < 聚合 < 组合 < 泛化/实现（后两者是继承关系，不是组合强弱）。

**多重度**：`1`（恰好一个）、`0..1`（零或一个）、`*`（零或多个）、`1..*`（至少一个）、`m..n`。

例："一个读者可以借多本书，一本书同一时刻只能被一个读者借" → 读者端 `1`，图书端 `0..*`（历史借阅）或 `0..1`（当前借阅），要看题目语义。

### 3.3 用例图

- 参与者：人或其他系统，用小人表示；
- 用例：椭圆，表示一个完整功能；
- **include**：必然发生的公共行为，箭头指向被包含用例（如"下单"include"登录校验"）；
- **extend**：可选/条件触发的扩展，箭头指向基础用例（如"支付"extend"使用优惠券"）；
- 泛化：参与者之间、用例之间的继承。

### 3.4 顺序图与状态图

**顺序图**：对象横向排列，生命线向下延伸，消息箭头表示调用，激活条表示对象正在执行。同步消息实心箭头、异步消息开口箭头、返回消息虚线箭头。组合片段 `alt`（分支）、`loop`（循环）、`opt`（可选）。

**状态图**：圆角矩形表示状态，实心圆表示初态，同心圆表示终态；迁移箭头标注"事件 [监护条件] / 动作"。

**活动图**：圆角矩形表示活动，菱形表示判定，粗横线表示并发分叉/汇合，泳道表示责任划分。

## 四、设计模式

### 4.1 创建型（5）

| 模式 | 一句话意图 |
| --- | --- |
| 单例 Singleton | 保证唯一实例 + 全局访问点 |
| 工厂方法 Factory Method | 定义创建接口，子类决定实例化哪个类 |
| 抽象工厂 Abstract Factory | 创建一系列相关对象（多产品族） |
| 建造者 Builder | 分步构建复杂对象，构建与表示分离 |
| 原型 Prototype | 通过克隆已有对象创建新对象 |

### 4.2 结构型（7）

| 模式 | 一句话意图 |
| --- | --- |
| 适配器 Adapter | 接口转换，让不兼容的类协同 |
| 桥接 Bridge | 抽象与实现分离，各自独立变化 |
| 组合 Composite | 树形结构表示整体-部分，统一对待 |
| 装饰 Decorator | 动态给对象添加职责 |
| 外观 Facade | 为子系统提供统一的高层接口 |
| 享元 Flyweight | 共享细粒度对象，节省内存 |
| 代理 Proxy | 控制对对象的访问 |

### 4.3 行为型（11）

| 模式 | 一句话意图 |
| --- | --- |
| 职责链 Chain of Responsibility | 请求沿链传递，直到被处理 |
| 命令 Command | 把请求封装为对象，支持撤销/排队 |
| 解释器 Interpreter | 给定语言定义文法并解释句子 |
| 迭代器 Iterator | 顺序访问聚合元素而不暴露内部 |
| 中介者 Mediator | 集中处理对象间的复杂交互 |
| 备忘录 Memento | 捕获并恢复对象内部状态 |
| 观察者 Observer | 一对多依赖，状态变化自动通知 |
| 状态 State | 状态改变时行为随之改变 |
| 策略 Strategy | 算法族可互换，客户端选择 |
| 模板方法 Template Method | 父类定骨架，子类实现步骤 |
| 访问者 Visitor | 在不改变元素类的前提下增加操作 |

### 4.4 场景关键词定位

| 题干关键词 | 模式 |
| --- | --- |
| 唯一实例、全局配置 | 单例 |
| 子类决定创建哪种产品 | 工厂方法 |
| 一套界面控件、多风格（Windows/Mac） | 抽象工厂 |
| 分步骤组装复杂对象（套餐、合同） | 建造者 |
| 复制已有对象、创建成本高 | 原型 |
| 接口不兼容、旧系统适配 | 适配器 |
| 抽象与实现两个维度独立扩展 | 桥接 |
| 树形菜单、文件目录统一处理 | 组合 |
| 动态加功能、可叠加（咖啡加料） | 装饰 |
| 一键启动子系统、简化调用 | 外观 |
| 大量相似对象共享（棋子、字符） | 享元 |
| 权限控制、延迟加载、远程代理 | 代理 |
| 多级审批、逐级处理 | 职责链 |
| 撤销、重做、操作排队 | 命令 |
| 自定义表达式/规则解析 | 解释器 |
| 统一遍历不同集合 | 迭代器 |
| 复杂网状交互、中心协调 | 中介者 |
| 存档/恢复、快照 | 备忘录 |
| 订阅通知、事件监听 | 观察者 |
| 状态迁移驱动行为（订单状态） | 状态 |
| 算法可替换（折扣、排序策略） | 策略 |
| 固定流程、步骤可变 | 模板方法 |
| 稳定数据结构上增加新操作 | 访问者 |

### 4.5 易混辨析

| 对比 | 区别 |
| --- | --- |
| 适配器 vs 桥接 | 适配器事后补救（已有类接口不合）；桥接事前设计（抽象与实现分离） |
| 策略 vs 状态 | 策略由客户端选算法；状态由对象内部迁移驱动 |
| 装饰 vs 代理 | 装饰叠加职责；代理控制访问（远程/延迟/权限） |
| 工厂方法 vs 抽象工厂 | 前者一类产品；后者一系列产品族 |
| 组合 vs 聚合 | 菱形都在整体端，实心才是强拥有 |
| 重载 vs 重写 | 重载同类同名不同参（编译期）；重写子类覆盖父类同名同参（运行期） |
| 外观 vs 中介者 | 外观简化单向调用；中介者协调多向交互 |

## 五、面向对象分析与设计

- **OOA（分析）**：从问题域识别对象、属性、服务与关系，建立类图/用例图，不涉及具体实现。
- **OOD（设计）**：在分析模型基础上补充接口、抽象类、设计模式、数据库映射等实现细节。
- **领域模型**：描述问题域概念（如"订单""客户"），不含技术细节；
- **设计模型**：描述实现结构（如"OrderDAO""PaymentService"），含技术决策。

OOA/OOD 都强调：高内聚低耦合、依赖抽象、单一职责、用例驱动、迭代增量。

## 七、易错辨析

| 错误认知 | 正确结论 | 原因 |
| --- | --- | --- |
| 聚合与组合的菱形画在部分端 | 画在整体端 | 菱形表示"整体"这一方 |
| include 是可选扩展 | include 是必然包含，extend 才可选 | 箭头方向与语义不同 |
| 策略模式由状态驱动 | 策略由客户端选择，状态由内部迁移驱动 | 两者意图不同 |
| 装饰模式改变对象接口 | 装饰保持接口不变、动态加职责 | 否则客户端无法透明使用 |
| 抽象工厂只创建一个产品 | 创建一系列相关产品（产品族） | 与工厂方法的区别 |
| 顺序图强调对象链接 | 顺序图强调时间顺序，通信图强调链接 | 两者侧重点不同 |
| 重写是编译期绑定 | 重写是运行期绑定 | 依赖对象实际类型 |

## 八、自检题

1. 组合与聚合的图形区别在哪一端？
2. 希望"动态给对象加功能"，选什么模式？
3. 一个系统要支持多种数据库驱动切换，用什么模式？
4. `include` 与 `extend` 的使用场景区别？
5. 单例模式的关键实现要点？
6. 顺序图与通信图各自的侧重点是什么？
7. "多级审批、逐级处理"适合什么模式？
8. 抽象工厂与工厂方法的核心区别？
9. 状态图适合描述什么？活动图的并发如何表示？
10. 依赖倒置原则的含义是什么？

> 答案与解析：
> 1) 菱形都画在"整体"一端，实心为组合、空心为聚合。
> 2) 装饰模式。
> 3) 桥接（抽象与实现分离）或策略（算法可替换），看是否需要整体替换实现；答桥接更稳。
> 4) include 是必然包含的公共行为；extend 是条件/可选扩展。
> 5) 私有构造 + 静态私有实例 + 静态公共获取方法；并发下用双检锁或静态内部类。
> 6) 顺序图强调消息的时间顺序；通信图强调对象之间的链接关系。
> 7) 职责链模式。
> 8) 工厂方法创建一类产品；抽象工厂创建一系列相关产品（产品族）。
> 9) 状态图描述单个对象在生命周期内的状态与迁移；活动图用同步条（粗横线）表示并发分叉与汇合。
> 10) 高层模块与低层模块都依赖抽象，抽象不依赖细节，细节依赖抽象。
