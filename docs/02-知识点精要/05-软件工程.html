05 · 软件工程（上午 13 题 · 第一大模块）

这一篇是上午卷分值最高的单模块，也是下午 DFD/UML 题的基础。四张表必须默写：模型对比、耦合 7 级、内聚 7 级、覆盖强度。

一、开发模型对比

模型核心特征适用场景主要缺点
瀑布阶段严格串行、文档驱动需求明确稳定、团队熟悉领域难以响应变更，后期才见产品
原型快速构建可运行版本澄清需求需求不明确原型可能被误当产品
增量分批交付可用版本可分块交付、希望早见效需良好架构规划
螺旋增量 + 原型 + 风险分析大型、高风险项目成本高、需风险评估能力
V 模型开发与测试一一对应强调测试的项目灵活性差
喷泉面向对象、迭代无缝OO 项目管理难度大
敏捷/Scrum迭代 sprint、可工作软件优先需求多变、小团队文档少、依赖团队素质
RUP用例驱动、以架构为中心、迭代增量中大型 OO 项目重量级、裁剪复杂

V 模型对应关系：需求分析 ↔ 验收测试；概要设计 ↔ 系统测试；详细设计 ↔ 集成测试；编码 ↔ 单元测试。

RUP 四阶段：初始（Inception）→ 细化（Elaboration）→ 构建（Construction）→ 交付（Transition）。

Scrum 三角色：Product Owner（需求与优先级）、Scrum Master（流程与障碍）、开发团队（交付增量）。

CMMI 五级：1 初始 → 2 已管理 → 3 已定义 → 4 量化管理 → 5 优化。

二、耦合（由低到高，越低越好）

级别名称含义
1非直接耦合模块间无直接联系
2数据耦合只传简单数据参数
3标记耦合传整个数据结构（记录）
4控制耦合传控制信息（标志位）
5外部耦合共同访问外部环境/设备
6公共耦合共同访问全局数据区
7内容耦合直接访问对方内部数据或代码

三、内聚（由高到低，越高越好）

级别名称含义
1功能内聚所有元素共同完成单一功能，缺一不可
2顺序内聚元素顺序执行，前一输出是后一输入
3通信内聚元素操作同一数据结构
4过程内聚元素按特定次序执行
5时间内聚元素在同一时间段执行（如初始化）
6逻辑内聚元素逻辑相似，由参数选择执行
7偶然内聚元素间无实质联系

模块化指标：扇入（被调用数，越大越好）、扇出（调用数，宜 3~4）、深度（层次）、宽度（同层模块数）。

四、详细设计与复杂度

McCabe 环形复杂度 V(G) = 边数 - 结点数 + 2
                      = 判定结点数 + 1
                      = 区域数

V(G) 也等于达到基本路径覆盖所需的最少测试用例数。

表达工具：程序流程图、N-S 图（盒图）、PAD 图、判定表/判定树、PDL。

五、软件测试

黑盒：等价类划分、边界值分析、错误推测、因果图、判定表、正交试验。

白盒覆盖强度（由弱到强）

语句覆盖 < 判定覆盖 < 条件覆盖 < 判定/条件覆盖 < 条件组合覆盖 < 路径覆盖
覆盖要求
语句覆盖每条可执行语句至少执行一次
判定覆盖每个判定的真、假分支各至少一次
条件覆盖每个判定中每个条件的取值至少一次
判定/条件覆盖同时满足判定覆盖与条件覆盖
条件组合覆盖每个判定中条件取值的所有组合至少一次
路径覆盖所有可能路径至少一次

测试阶段：单元测试（驱动模块 + 桩模块）→ 集成测试（自顶向下用桩、自底向上用驱动、三明治）→ 系统测试 → 验收测试（α/β）。

回归测试：修改后重跑既有用例，确认未引入新缺陷。冒烟测试：快速验证基本功能可用。

六、维护与项目管理

维护类型内容占比
改正性修复缺陷约 20%
适应性适应环境变化约 25%
改善性/完善性新增功能、优化性能最大，约 50%+
预防性提高可维护性较小

进度：Gantt 图直观但难表达依赖；PERT 网能表达依赖并算关键路径（最长路径，总时差为 0 的活动为关键活动）。

成本估算：COCOMO（基本/中间/详细）、Putnam、专家判断、类比估算。

风险应对：规避、转移、减轻、接受。

配置管理：配置项识别、基线、版本控制、变更控制（CCB）、配置审计。

质量特性（ISO 9126）：功能性、可靠性、易用性、效率、可维护性、可移植性。
可维护性包含：可理解性、可测试性、可修改性（易改变性）、稳定性、易分析性。
