## 二、云计算

### 2.1 定义与特征

云计算通过网络按需提供可配置的计算资源（网络、服务器、存储、应用、服务），用户按使用量付费。

五个基本特征：

1. 按需自服务：用户自助申请，无需人工干预；
2. 广泛网络接入：通过标准网络访问；
3. 资源池化：资源以池的形式共享，多租户隔离；
4. 快速弹性：可快速扩容与缩容；
5. 服务可计量：按使用量计费与监控。

### 2.2 三种服务模式

| 模式 | 提供内容 | 用户负责 | 典型例子 |
| --- | --- | --- | --- |
| IaaS | 虚拟机、存储、网络等基础设施 | 操作系统、中间件、应用、数据 | AWS EC2、阿里云 ECS |
| PaaS | 开发运行平台、中间件、数据库服务 | 应用与数据 | Google App Engine、Heroku |
| SaaS | 可直接使用的软件 | 只管使用与配置 | Office 365、企业邮箱、在线 CRM |

判断技巧：**用户是否要管操作系统**——要管是 IaaS；不管 OS 但要部署自己的应用是 PaaS；连应用都不用开发、直接使用是 SaaS。

### 2.3 部署形态

| 形态 | 特点 |
| --- | --- |
| 公有云 | 云服务商运营，多租户共享，成本低 |
| 私有云 | 企业自建自用，安全可控，成本高 |
| 混合云 | 关键业务私有云、弹性业务公有云 |
| 社区云 | 特定群体（如某行业）共同使用 |

### 2.4 虚拟化与容器

| 对比 | 虚拟机 | 容器 |
| --- | --- | --- |
| 隔离层次 | 硬件级，含完整 Guest OS | 进程级，共享宿主机内核 |
| 启动速度 | 分钟级 | 秒级 |
| 资源开销 | 大 | 小 |
| 隔离性 | 强 | 较弱 |
| 典型 | VMware、KVM | Docker、containerd |

**云原生**四要素：容器化、微服务、DevOps、持续交付。Kubernetes 是容器编排的事实标准，负责调度、扩缩容、服务发现。

## 三、大数据

### 3.1 4V 特征

| 特征 | 含义 |
| --- | --- |
| Volume | 数据体量大（TB/PB 级） |
| Velocity | 产生与处理速度快，实时性要求高 |
| Variety | 类型多样：结构化、半结构化、非结构化 |
| Value | 价值密度低，需从海量数据中挖掘 |

扩展的第五个 V 是 Veracity（真实性/质量），强调数据可信度。

### 3.2 处理流程

```
数据采集 → 预处理（清洗、集成、变换、归约）→ 存储 → 分析挖掘 → 可视化
```

### 3.3 Hadoop 生态

| 组件 | 作用 |
| --- | --- |
| HDFS | 分布式文件系统，NameNode 管元数据、DataNode 存数据块，多副本 |
| MapReduce | 批处理计算模型，Map 分片处理、Reduce 汇总 |
| YARN | 资源调度，ResourceManager 全局、NodeManager 单机 |
| Hive | 类 SQL 数据仓库，把 SQL 转为 MapReduce/Spark 任务 |
| HBase | 基于 HDFS 的列式 NoSQL 数据库，适合随机读写 |
| Spark | 内存计算，比 MapReduce 快，支持批处理与流处理 |

### 3.4 批处理与流处理

| 类型 | 数据形态 | 延迟 | 典型 |
| --- | --- | --- | --- |
| 批处理 | 有界、已落地 | 分钟~小时 | MapReduce、Hive |
| 流处理 | 无界、持续到达 | 毫秒~秒 | Flink、Spark Streaming、Storm |

**数据仓库 vs 数据湖**：数据仓库存结构化、已建模数据（schema-on-write），适合 BI 报表；数据湖存原始数据（schema-on-read），适合探索式分析与机器学习。

## 四、人工智能

### 4.1 三大研究取向

| 取向 | 核心思想 | 代表 |
| --- | --- | --- |
| 符号主义 | 用符号与逻辑规则模拟智能 | 专家系统、知识图谱、逻辑推理 |
| 连接主义 | 用神经网络模拟大脑连接 | 深度学习、大模型 |
| 行为主义 | 智能体在与环境交互中学习 | 强化学习、机器人 |

### 4.2 机器学习分类

| 类型 | 数据 | 任务 | 典型算法 |
| --- | --- | --- | --- |
| 监督学习 | 有标签 | 分类、回归 | 线性回归、逻辑回归、决策树、SVM、KNN、随机森林 |
| 无监督学习 | 无标签 | 聚类、降维 | K-means、DBSCAN、PCA |
| 半监督学习 | 少量标签 + 大量无标签 | 分类 | 自训练、图半监督 |
| 强化学习 | 奖励信号 | 序列决策 | Q-learning、DQN、策略梯度 |

### 4.3 深度学习主干

| 结构 | 擅长 | 典型应用 |
| --- | --- | --- |
| CNN | 图像、局部特征、卷积与池化 | 图像分类、目标检测、人脸识别 |
| RNN/LSTM | 序列、时序依赖 | 语音识别、文本生成、股价预测 |
| Transformer | 自注意力、长距离依赖、可并行 | 机器翻译、大语言模型、多模态 |

### 4.4 大模型与生成式 AI

- **预训练**：在海量无标注语料上自监督学习，得到基础模型；
- **微调（SFT）**：用标注数据调整模型以适应具体任务；
- **RLHF**：基于人类反馈的强化学习，使输出更符合人类偏好；
- **提示工程**：通过设计输入提示引导模型输出；
- **RAG（检索增强生成）**：先检索外部知识库再生成，缓解幻觉、保证时效性；
- **幻觉**：模型生成看似合理但与事实不符的内容，是大模型的主要风险之一。

常见应用：计算机视觉、自然语言处理（翻译、摘要、问答）、语音识别与合成、推荐系统、自动驾驶。

### 4.5 过拟合与评估

过拟合：模型在训练集表现好、测试集表现差。对策：增加数据、正则化（L1/L2）、Dropout、早停、交叉验证、简化模型。

评估指标：准确率、精确率、召回率、F1、ROC-AUC；回归用 MSE/MAE/R²。

## 五、物联网与 5G

### 5.1 物联网架构

| 层次 | 作用 | 典型技术/设备 |
| --- | --- | --- |
| 感知层 | 数据采集与识别 | 传感器、RFID、二维码、摄像头 |
| 网络层 | 数据传输 | NB-IoT、LoRa、ZigBee、4G/5G |
| 平台层 | 设备管理、数据汇聚 | 物联网平台、边缘网关 |
| 应用层 | 业务呈现 | 智能家居、车联网、工业互联网 |

三特征：全面感知、可靠传输、智能处理。

### 5.2 物联网通信技术

| 技术 | 特点 | 适用 |
| --- | --- | --- |
| NB-IoT | 窄带、低功耗、广覆盖、大连接、成本低 | 抄表、井盖、环境监测 |
| LoRa | 远距离、低功耗、自组网 | 园区、农业 |
| ZigBee | 短距离、低功耗、Mesh 组网 | 智能家居 |
| 5G | 高速率、低时延、大连接 | 车联网、工业控制 |

### 5.3 5G 三大场景

| 场景 | 全称 | 特点 | 应用 |
| --- | --- | --- | --- |
| eMBB | 增强移动宽带 | 高速率 | 4K/8K 视频、VR/AR |
| mMTC | 海量机器类通信 | 高连接密度、低功耗 | 智慧城市、传感器网络 |
| uRLLC | 低时延高可靠 | 毫秒级时延、高可靠 | 远程手术、车联网、工业控制 |

## 六、区块链与边缘计算

### 6.1 区块链特征

| 特征 | 含义 |
| --- | --- |
| 去中心化 | 无单一中心节点，节点共同维护 |
| 不可篡改 | 区块哈希链式相连，修改需重算后续所有区块 |
| 可追溯 | 每笔交易有完整历史记录 |
| 公开透明 | 公有链数据对所有节点可见 |
| 集体维护 | 共识机制保证各节点账本一致 |

核心技术：哈希链、数字签名、共识机制、智能合约、P2P 网络。

### 6.2 三种链与共识机制

| 类型 | 准入 | 典型 | 特点 |
| --- | --- | --- | --- |
| 公有链 | 任何人可加入 | 比特币、以太坊 | 完全去中心化，性能较低 |
| 联盟链 | 许可节点加入 | Hyperledger Fabric | 多机构共享，兼顾效率与可控 |
| 私有链 | 单一组织内部 | 企业内部账本 | 中心化程度高，性能好 |

| 共识机制 | 原理 | 适用 |
| --- | --- | --- |
| PoW | 算力竞争解题，最长链胜出 | 公有链，能耗高 |
| PoS | 按权益（持币量）选记账人 | 公有链，能耗低 |
| PBFT | 多轮投票达成拜占庭容错 | 联盟链，确定性强、节点数受限 |

**不可能三角**：去中心化、安全性、可扩展性三者难以同时最优。

**智能合约**：部署在链上的自动执行代码，条件满足即触发，不可篡改。

### 6.3 边缘计算

把计算、存储、网络能力下沉到靠近数据源的一侧（网关、基站、设备），就近处理。

价值：降低时延、减少回传带宽、本地数据不出域（隐私）、支持离线自治。与云计算是**云边协同**关系：边缘做实时处理，云端做全局分析与模型训练。

相关概念：数字孪生（物理实体的虚拟映射）、AR/VR（增强/虚拟现实）、微服务（独立部署的小服务）、容器编排（Kubernetes）。

## 八、易错辨析

| 错误认知 | 正确结论 | 原因 |
| --- | --- | --- |
| IaaS 提供开发平台 | IaaS 只提供基础设施，PaaS 才提供平台 | 责任边界不同 |
| SaaS 需要用户部署应用 | SaaS 直接使用软件 | 应用由服务商托管 |
| 大数据价值密度高 | 价值密度低，需挖掘 | 单条数据价值有限 |
| 容器是轻量虚拟机 | 容器共享宿主机内核，不是虚拟化硬件 | 隔离机制不同 |
| 无监督学习需要标签 | 不需要标签 | 聚类/降维靠数据相似性 |
| Transformer 只能做文本 | 也可用于图像、多模态 | 自注意力是通用结构 |
| 区块链绝对安全 | 存在 51% 攻击、合约漏洞等风险 | 不可篡改依赖共识 |
| 边缘计算替代云计算 | 云边协同，不是替代 | 各自承担不同任务 |
| NB-IoT 适合视频监控 | NB-IoT 带宽低，适合小数据 | 视频需高带宽 |

## 九、自检题

1. 用户通过浏览器直接使用在线文档，属于 IaaS、PaaS 还是 SaaS？（对应题库 TECH-001）
2. 容器与虚拟机的主要区别是什么？（对应题库 TECH-003）
3. 大数据 4V 分别指什么？"价值密度低"如何理解？（对应题库 TECH-004）
4. HDFS 中 NameNode 与 DataNode 各负责什么？（对应题库 TECH-005）
5. 对实时传感器数据做毫秒级告警，应选批处理还是流处理？（对应题库 TECH-006）
6. 无标签数据的聚类属于哪类机器学习？（对应题库 TECH-007）
7. CNN、RNN、Transformer 各擅长什么？（对应题库 TECH-008）
8. 物联网三层架构分别包含哪些设备/技术？（对应题库 TECH-009）
9. 5G 三大场景分别面向什么业务？（对应题库 TECH-011）
10. 公有链与联盟链的共识机制有何不同？（对应题库 TECH-010）
11. 边缘计算的核心价值是什么？（对应题库 TECH-012）
12. RAG 能缓解大模型的什么问题？（对应题库 TECH-008）

> 答案与解析：
> 1) SaaS。
> 2) 容器共享宿主机内核、启动快、开销小；虚拟机含完整 Guest OS、隔离性强。
> 3) Volume 体量大、Velocity 速度快、Variety 类型多、Value 价值密度低；单条数据价值有限，需大规模分析提炼。
> 4) NameNode 管理命名空间与元数据；DataNode 存储数据块并定期汇报。
> 5) 流处理（Flink/Spark Streaming）。
> 6) 无监督学习。
> 7) CNN 图像、RNN 序列、Transformer 长距离依赖与并行（大模型基础）。
> 8) 感知层（传感器、RFID、摄像头）、网络层（NB-IoT、LoRa、5G）、应用层（智能家居、车联网等）。
> 9) eMBB 高速率、mMTC 大连接、uRLLC 低时延高可靠。
> 10) 公有链常用 PoW/PoS，开放但性能较低；联盟链常用 PBFT，节点受控、确定性强。
> 11) 就近处理，降低时延与回传带宽，保护本地数据隐私，与云端协同。
> 12) 缓解幻觉、补充时效性知识（先检索外部知识再生成）。
