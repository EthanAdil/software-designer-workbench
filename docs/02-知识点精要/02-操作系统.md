## 二、进程与线程

### 2.1 进程的定义与 PCB

进程是程序在一个数据集合上的一次运行过程，是系统进行资源分配和调度的基本单位。进程实体由**程序段、数据段、PCB** 三部分组成。

**PCB（进程控制块）是进程存在的唯一标志**。操作系统通过 PCB 感知进程、保存现场（程序计数器、寄存器、状态字）、记录资源清单。题目问"进程存在的标志"或"进程切换时保存现场的地方"，答案都是 PCB。

### 2.2 进程状态

```
三态：就绪 → 运行 → 阻塞 → 就绪
五态：新建 → 就绪 ⇄ 运行 → 终止，运行 → 阻塞 → 就绪
```

三条不能发生的转换：

- 阻塞 → 运行：必须先回到就绪队列，等待调度；
- 就绪 → 阻塞：就绪进程没有 CPU，无法发起 I/O 请求；
- （五态中）终止 → 其他状态。

**转换的触发者**：就绪→运行由调度程序触发；运行→就绪由时间片到或被抢占触发；运行→阻塞由进程自身请求 I/O 或等待事件触发；阻塞→就绪由等待的事件完成触发。

### 2.3 线程

线程是 CPU 调度的基本单位。同一进程内的线程**共享**地址空间、全局变量、打开的文件等资源，但**各自独立**拥有栈、寄存器上下文、程序计数器。

对比：进程切换要切换地址空间（开销大），线程切换在同一地址空间内完成（开销小）。用户级线程由线程库管理、内核不可见；内核级线程由内核调度、可多核并行。

### 2.4 进程通信

| 方式 | 特点 |
| --- | --- |
| 共享存储 | 最快，需同步互斥保护 |
| 消息传递 | 通过发送/接收消息，适合分布式 |
| 管道 | 半双工、字节流，有亲缘关系的进程常用 |
| 信号 | 异步通知，用于事件处理 |

## 三、PV 操作与同步

### 3.1 信号量语义

```
P(S)：S = S - 1；若 S < 0，则阻塞当前进程
V(S)：S = S + 1；若 S ≤ 0，则唤醒一个等待进程
```

S 的取值含义：

| S 值 | 含义 |
| --- | --- |
| S > 0 | 还有 S 个可用资源 |
| S = 0 | 资源刚好用完，无进程等待 |
| S < 0 | 有 S 个进程在等待资源，-S个资源被占用 |

注意 P 是"先减再判断"，V 是"先加再判断"。顺序写反，整道题全错。

### 3.2 生产者-消费者（缓冲区容量 n）

| 信号量 | 初值 | 含义 |
| --- | --- | --- |
| mutex | 1 | 互斥访问缓冲区 |
| empty | n | 空闲槽位数 |
| full | 0 | 已放产品数 |

```
生产者：P(empty) → P(mutex) → 放入产品 → V(mutex) → V(full)
消费者：P(full)  → P(mutex) → 取出产品 → V(mutex) → V(empty)
```

**顺序不可颠倒**：先 P 资源信号量、再 P 互斥信号量。若先 P(mutex) 再 P(empty)，缓冲区满时生产者持锁等待，消费者无法进入临界区取产品，形成死锁。

### 3.3 读者-写者（读优先）

```
count = 0；mutex = 1（保护 count）；rw = 1（读写互斥）

读者：P(mutex) → count++ → 若 count==1 则 P(rw) → V(mutex) → 读 → P(mutex) → count-- → 若 count==0 则 V(rw) → V(mutex)
写者：P(rw) → 写 → V(rw)
```

考试若只考初值，记"互斥信号量初值 1、同步信号量初值 0（或资源数）"即可。

## 四、死锁

### 4.1 四个必要条件

互斥、请求并保持、不可剥夺、环路等待。四个条件**同时满足**才可能死锁，破坏任意一个即可预防。

| 策略 | 做法 | 代价 |
| --- | --- | --- |
| 预防 | 破坏四个条件之一（如一次申请全部资源） | 资源利用率低 |
| 避免 | 银行家算法，分配前判断是否安全 | 需预知最大需求 |
| 检测 | 资源分配图化简、找环 | 需定期运行检测算法 |
| 解除 | 撤销进程或剥夺资源 | 实现复杂 |

### 4.2 银行家算法

系统维护 Available（可用资源）、Max（最大需求）、Allocation（已分配）、Need = Max - Allocation。每次试分配后检查是否存在**安全序列**：找一个 Need ≤ Available 的进程，假设它完成并释放资源，重复直到所有进程完成。

**例**：三类资源 A/B/C，Available = (3,3,2)。

| 进程 | Allocation | Need |
| --- | --- | --- |
| P0 | (0,1,0) | (7,4,3) |
| P1 | (2,0,0) | (1,2,2) |
| P2 | (3,0,2) | (6,0,0) |
| P3 | (2,1,1) | (0,1,1) |
| P4 | (0,0,2) | (4,3,1) |

求解：P1 的 Need (1,2,2) ≤ (3,3,2)，先完成 P1，Available 变为 (5,3,2)；接着 P3 可完成 → (7,4,3)；P4 可完成 → (7,4,5)；P0 可完成 → (7,5,5)；P2 最后完成。安全序列为 `P1 → P3 → P4 → P0 → P2`（P2 与 P0 顺序可交换）。

考试通常只问"下列哪个是安全序列"，按上述步骤逐个验证选项即可。

## 五、存储管理

### 5.1 页式、段式、段页式

| 方式 | 地址结构 | 碎片 | 特点 |
| --- | --- | --- | --- |
| 页式 | 页号 + 页内地址 | 内部碎片 | 无外部碎片，页表存于内存，TLB 加速 |
| 段式 | 段号 + 段内地址 | 外部碎片 | 按逻辑划分，便于共享与保护 |
| 段页式 | 段号 + 页号 + 页内地址 | 内部碎片 | 两次查表，开销最大 |

**地址换算**：页面大小 4KB = `0x1000`，低 12 位是页内偏移。例：逻辑地址 `0x2A5F` → 页号 `2`、偏移 `0xA5F`。计算时先把页面大小写成 2 的幂，再按位切分，比除法快。

### 5.2 虚拟存储

虚拟存储利用局部性原理，只把当前用到的页调入内存，其余留在辅存，从而用较小的物理内存运行较大的程序。

- **缺页中断**：访问的页不在内存，触发中断调页；
- **抖动（颠簸）**：分配的物理块不足，刚换出的页立刻又要换入，CPU 大部分时间耗在换页上；
- **工作集**：进程在某段时间内实际访问的页面集合，用于给进程分配足够的物理块。

### 5.3 页面置换

| 算法 | 规则 | 特点 |
| --- | --- | --- |
| OPT | 淘汰未来最长时间不用的页 | 理论最优，无法实现，作基准 |
| FIFO | 淘汰最早进入的页 | 简单，存在 Belady 异常 |
| LRU | 淘汰最近最久未使用的页 | 接近 OPT，需硬件支持 |
| LFU | 淘汰访问次数最少的页 | 对突发访问不友好 |

**Belady 异常**：增加物理块数，缺页次数反而增加，只出现在 FIFO 一类算法中，LRU 不会。

**例**：3 个物理块，引用串 `1,2,3,4,1,2,5,1,2,3,4,5`，LRU 缺页次数。

| 访问 | 内存块（左为最久未用） | 结果 |
| --- | --- | --- |
| 1 | 1 | 缺 |
| 2 | 1,2 | 缺 |
| 3 | 1,2,3 | 缺 |
| 4 | 2,3,4 | 缺（淘汰 1） |
| 1 | 3,4,1 | 缺（淘汰 2） |
| 2 | 4,1,2 | 缺（淘汰 3） |
| 5 | 1,2,5 | 缺（淘汰 4） |
| 1 | 2,5,1 | 命中 |
| 2 | 5,1,2 | 命中 |
| 3 | 1,2,3 | 缺（淘汰 5） |
| 4 | 2,3,4 | 缺（淘汰 1） |
| 5 | 3,4,5 | 缺（淘汰 2） |

缺页 10 次。手算时维护"最近使用顺序"一行，比画三格更容易检查。

## 六、文件管理

### 6.1 物理结构

| 结构 | 随机访问 | 扩展 | 碎片 | 适用 |
| --- | --- | --- | --- | --- |
| 连续 | 支持 | 困难 | 外部碎片 | 顺序读写、只读文件 |
| 链接 | 不支持，只能顺序 | 容易 | 无 | 顺序文件、日志 |
| 索引 | 支持 | 容易 | 索引表占空间 | 随机访问的大文件 |

**索引文件容量**：一级索引可寻址 `块大小 / 索引项大小` 个块，再乘块大小。例：块 1KB、索引项 4B → 256 个块 → 最大 256KB。

**多级混合索引（真题考点）**：inode 前 5 项直接地址对应逻辑块 0~4，第 5 项起进入一级间接；1KB 索引块 / 4B 地址项 → 每块 256 项，二级间接可达 `256²` 块。`5 直接 + 2 一级间接 + 1 二级间接` 时最大单文件长度 = `(5 + 2×256 + 256²) × 1KB = 66053KB`。访问逻辑块 4 用直接地址，块 5 用一级间接。

### 6.2 目录与 inode

- 绝对路径从根目录开始，相对路径从当前目录开始；
- 索引结点（inode）把文件名与文件属性分离：目录项只存"文件名 + inode 号"，inode 存权限、大小、物理地址等；
- 硬链接共享 inode，删除一个名字不删数据；软链接是独立的文件，存目标路径。

### 6.3 空闲空间管理

**位示图**：每一位对应一个物理块，1 表示占用、0 表示空闲。

```
字号 = 物理块号 / 字长（整数除法）
位号 = 物理块号 % 字长
物理块号 = 字号 × 字长 + 位号
```
例：字长 32、块号 100 → 字号 `100/32 = 3`、位号 `100%32 = 4`。

**位示图大小（真题考点）**：位数等于磁盘物理块数，`字数 = ⌈物理块数 / 字长⌉`。例：512GB 磁盘、块 4MB → 131072 块，字长 64 → `131072/64 = 2048` 个字。

其他方式：空闲表、空闲链表、成组链接（UNIX 使用，把空闲块分组，每组第一块记录下一组的块号）。

## 七、设备管理

### 7.1 磁盘调度

| 算法 | 策略 | 缺点 |
| --- | --- | --- |
| FCFS | 按请求到达顺序 | 移臂距离大 |
| SSTF | 先服务离当前磁头最近的请求 | 远端请求可能饥饿 |
| SCAN（电梯） | 单向扫描到端点再折返 | 边缘磁道等待久 |
| CSCAN | 到端点直接回到起点，单向服务 | 回程不服务 |

**例**：磁头当前在 53，请求序列 `98,183,37,122,14,124,65,67`，SSTF 的总移道数。

```
53 → 65(12) → 67(2) → 37(30) → 14(23) → 98(84) → 122(24) → 124(2) → 183(59)
总移道数 = 12+2+30+23+84+24+2+59 = 236
```
SCAN 题要先确认初始方向（向大或向小），方向不同结果不同，题干没写时按"向磁道号增大方向"处理并注明。

### 7.2 SPOOLing 与缓冲

SPOOLing 用磁盘上的输入井/输出井把独占设备虚拟成共享设备，典型应用是打印缓冲：多个进程的打印任务先落盘排队，再由守护进程依次送打印机。

缓冲：单缓冲使处理与传输部分重叠；双缓冲进一步减少等待；缓冲池供多个进程共享。

## 八、作业与进程调度

```
周转时间 = 完成时间 - 到达时间
带权周转时间 = 周转时间 / 服务时间
平均周转时间 = Σ周转时间 / 作业数
```

| 算法 | 特点 |
| --- | --- |
| FCFS | 公平、实现简单，短作业等待久 |
| SJF | 平均等待/周转时间最短，长作业可能饥饿 |
| 优先级 | 可静态或动态，动态优先级可缓解饥饿 |
| 时间片轮转 | 响应快，时间片过大退化为 FCFS，过小切换开销大 |
| 多级反馈队列 | 兼顾响应与吞吐，新进程进高优先级队列 |

**可剥夺 vs 不可剥夺（真题考点）**：调度方式按运行进程能否被强行撤下分两类——高优先级进程抢占正在运行进程的 CPU 属**可剥夺（抢占式）**，时间片轮转与多级反馈队列也是抢占式；FCFS/SJF 通常为不可剥夺。注意与死锁四条件中的「不可剥夺」区分，不是同一语境。

**例**：4 个作业 `(到达, 服务) = (0,3)、(2,6)、(4,4)、(6,5)`，FCFS 调度。

| 作业 | 开始 | 完成 | 周转 | 带权 |
| --- | --- | --- | --- | --- |
| J1 | 0 | 3 | 3 | 1.00 |
| J2 | 3 | 9 | 7 | 1.17 |
| J3 | 9 | 13 | 9 | 2.25 |
| J4 | 13 | 18 | 12 | 2.40 |

平均周转时间 `(3+7+9+12)/4 = 7.75`，平均带权周转时间 `(1+1.17+2.25+2.4)/4 ≈ 1.70`。

## 九、速记表

```
三态：就绪→运行→阻塞→就绪；阻塞不能直接回运行
P：减 1 再判断；V：加 1 再判断
S<0 时 |S| = 等待进程数
互斥信号量初值 1；同步信号量初值 0 或资源数
死锁四条件：互斥、请求并保持、不可剥夺、环路等待
页内地址位数 = log2(页面大小)
字号 = 块号 / 字长；位号 = 块号 % 字长
周转 = 完成 - 到达；带权 = 周转 / 服务
```

## 十、易错辨析

| 错误认知 | 正确结论 | 原因 |
| --- | --- | --- |
| 阻塞可以直接转为运行 | 必须先转就绪，再被调度 | 阻塞结束时 CPU 可能正被占用 |
| 信号量为负表示资源数为负 | 负值的绝对值是等待进程数 | 资源数最少为 0 |
| 先 P(mutex) 再 P(empty) 更安全 | 顺序反了会死锁 | 持锁等待资源，消费者进不来 |
| 页式存储有外部碎片 | 页式只有内部碎片 | 页大小固定，最后一页可能浪费 |
| 增加物理块一定减少缺页 | FIFO 可能出现 Belady 异常 | 淘汰策略与访问序列不匹配 |
| 磁盘调度 SSTF 最优 | SSTF 只是每次最近，可能饥饿 | 全局最优需 SCAN 类策略 |
| 线程有独立地址空间 | 同进程线程共享地址空间 | 线程只独占栈和寄存器 |

## 十一、自检题

1. 信号量初值 3，当前值 -1，说明什么？（对应题库 OS-004）
2. 生产者-消费者中，若把 `P(empty)` 与 `P(mutex)` 顺序颠倒，会发生什么？（对应题库 OS-038）
3. 死锁的四个必要条件是什么？银行家算法属于哪种策略？（对应题库 OS-005 / OS-006）
4. 页面大小 8KB，逻辑地址 `0x3FFF` 的页号与页内偏移是多少？（对应题库 OS-007）
5. 3 个物理块，引用串 `1,2,3,4,1,2,5`，FIFO 的缺页次数是多少？（对应题库 OS-008）
6. 字长 32、块号 100，位示图的字号和位号是多少？（对应题库 OS-011）
7. 磁头在 50，请求 `10,20,30,40,60`，SSTF 的总移道数是多少？（对应题库 OS-034）
8. 4 个作业 FCFS，如何计算平均带权周转时间？（对应题库 OS-013）
9. 为什么说"增加物理块可能让 FIFO 缺页更多"？（对应题库 OS-009）
10. 线程切换为什么比进程切换快？（对应题库 OS-017）

> 答案与解析：
> 1) 3 个资源已全部分配，另有 1 个进程在等待。
> 2) 缓冲区满时生产者持锁等待 empty，消费者无法进入临界区取产品，形成死锁。
> 3) 互斥、请求并保持、不可剥夺、环路等待；银行家算法属于死锁避免。
> 4) `0x3FFF = 16383`，页大小 8192 → 页号 1、偏移 `0x1FFF`。
> 5) 1,2,3 缺 3 次；4 淘汰 1；1 淘汰 2；2 淘汰 3；5 淘汰 4 → 共 7 次。
> 6) 字号 3、位号 4。
> 7) `50→60(10)→40(20)→30(10)→20(10)→10(10)`，共 60。
> 8) 先算每个作业的完成时间，再算周转时间（完成-到达），最后除以服务时间取平均。
> 9) FIFO 只看进入时间，不看访问频率，块数变化会改变淘汰顺序，可能出现 Belady 异常。
> 10) 线程共享同一地址空间，切换时无需切换页表与地址空间，只需保存寄存器与栈。
