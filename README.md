# 软件设计师（软考中级）备考工作台

面向 **2027 年上半年 · 软件设计师** 的系统化备考项目：四阶段 29 周计划 + 13 模块要点速览 + 11 篇知识精讲 + 607 道自编上午题（首轮 531 + 真题 topic 对照补充 76；含 37 道专业英语）+ 24 道下午案例 + 318 道历年真题（2020 下 / 2021 上 / 2022 上 / 2022 下 / 2023 上 / 2023 下 / 2024 上 / 2024 下上午卷）+ 4 套阶段测评 + 8 套模拟考试 + 4 套下午卷。

参考了 GitHub 上主流软考项目的组织方式（`xiaomabenten/software_designer` 的资料体系、`chenguanghua/soft-exam-web` 的纯静态学习站形态），做成**零依赖、双击即用**的本地工作台。

> **范围边界**：面向个人本地备考，不分发官方真题原文；2025/2026 真题与依赖配图 / 表格 / 代码的题目因缺少「题面 + 答案可交叉核对」的材料未入库，下午卷仅收录自编案例（24 道）；不含 npm / 服务端 / 团队协同形态。当前待办与材料缺口见 `docs/平台开发/当前任务计划.md`，已完成明细与审计归档见 `docs/平台开发/开发任务清单.md`。

## 快速开始

双击 `index.html` 即可（Chrome / Edge / Firefox 均可，无需安装任何东西、无需起服务）。

如果浏览器限制了本地文件脚本，用任意静态服务打开：

```bash
python -m http.server 8731
# 然后访问 http://localhost:8731
```

> 8731 是刻意选的冷门端口，避免和本机常驻服务（8080、8000、3000 等）撞车；若仍被占用，换任意四位数即可。

> **文档编码**：`docs/` 下的 `.md` 是源文件，`.html` 是生成物（改完 `.md` 执行 `node tools/build-docs.js` 刷新）。HTML 头部已声明 `<meta charset="utf-8">`，用浏览器打开 `.html` 不会乱码；直接打开 `.md` 时个别浏览器会按系统 GBK 猜测编码，从而显示成乱码。

> 手机上如何运行和使用，见「移动端使用」。

## 移动端使用

手机不能直接双击 `index.html`，要让它通过 HTTP 访问**整个项目目录**：入口依赖 `assets/js/` 下的题库与视图脚本、`assets/css/` 样式，以及 `docs/` 下的精讲 HTML；只拷单个 HTML 会白屏。三种方式任选其一。

**方式一 · 局域网静态服务（推荐，免部署）**

1. 手机与电脑连同一 Wi-Fi；电脑在项目根执行（Windows PowerShell 先 `cd f:\Project\Dev\Soft`）：
   ```bash
   python -m http.server 8731 --bind 0.0.0.0
   ```
   `--bind 0.0.0.0` 不能省，否则手机连不上。
2. 电脑执行 `ipconfig`，记下「无线局域网适配器 WLAN」的 IPv4，如 `192.168.1.23`。
3. 手机浏览器打开 `http://192.168.1.23:8731/`（换成自己的 IP，保留结尾 `/`）。
4. 连不上时：Windows 防火墙首次需允许 Python 通过「专用网络」，或放行 8731 端口。
5. 用完 `Ctrl+C` 停止；服务关闭后手机无法访问，下次重做第 1 步。

**方式二 · GitHub Pages（长期用，不需电脑常开）**

Gitee Pages 已于 2024 年下线（官方回复「不可抗原因，暂无恢复计划」），`*.gitee.io` 地址不可用。本项目的 Gitee 仓库只作源码托管，公网访问走 GitHub Pages。

1. 保留现有 `origin`（Gitee），另加 GitHub 远端并首次推送：

   ```bash
   git remote add github git@github.com:EthanAdil/software-designer-workbench.git
   git push -u github master
   ```

2. GitHub 仓库 → Settings → Pages → Source 选 `Deploy from a branch`，分支选 `master`（与本地一致）、目录 `/(root)` → Save。
3. 等 1~2 分钟，手机访问 `https://ethanadil.github.io/software-designer-workbench/`。
4. 之后每次改完内容推两个远端：`git push origin master`（Gitee 源码备份）、`git push github master`（触发 Pages 更新）。
5. 两个仓库都会公开；`progress/` 已移出主仓库，由 Gitee 私有仓库单独托管，不会出现在这里。
6. GitHub Pages 国内访问偶有波动，打不开时回退方式一（局域网）。

**方式三 · 手机本地文件（不推荐）**

把整个目录拷进手机，用文件管理器选支持 `file://` 的浏览器打开 `index.html`。Android 部分浏览器可用但常限制脚本加载，iOS Safari 基本加载不了相对脚本与 `localStorage`，建议改用方式一或二。

**手机上的操作步骤**

1. 打开默认进「总览」。窄屏（≤980px）左侧栏变成**顶部横向滚动导航**，左右滑切换 10 个页面：总览 / 学习计划 / 知识模块 / 备考文档 / 刷题练习 / 真题题库 / 阶段测评 / 模拟考试 / 错题本 / 成绩分析；右上角「切换主题」切深浅色。
2. 每天：总览看本周任务 → 学习计划勾选打卡 → 刷题练习（自选模块 / 随机 / 按模块 / 错题重做）→ 真题题库（按模块 / 按年份）→ 错题本填「错因」与「一句话结论」。
3. 每周：补完打卡，到成绩分析看成绩趋势 +「模块掌握度雷达」+「每周已完成计划时长」（图表自适应屏宽）。
4. 看精讲：备考文档或知识模块点「打开文档」，会在**新标签**打开 `docs/02-知识点精要/*.html`；宽表格与代码块可左右滑，页面顶部「← 返回工作台」回入口。
5. 考试：阶段测评 / 模拟考试在窄屏下把计时器与答题卡移到题目下方；**考试中不要刷新页面**，刷新会丢本次作答。
6. 打印：手机浏览器「分享 → 打印 / 存储为 PDF」；A4 排版建议在电脑 `Ctrl+P` 核对（纸张 A4、边距默认、勾选「背景图形」）。
7. 可「添加到主屏幕」当快捷方式；本项目不是 PWA，没有离线缓存，局域网服务关闭或断网就打不开。

**数据同步（手机与电脑不互通）**

进度只存在当前设备、当前浏览器的 `localStorage`（详见「数据存储」）。搬运数据：错题本 → 数据管理 →「导出备份（JSON · v2）」→ 把文件传到另一台设备 →「导入备份（JSON）」；完整导出含自编与真题全部 8 类，选择性导出只含勾选类别；**导入会按备份中的类别覆盖本机对应数据，未包含的类别保持本机不变**，覆盖前有弹窗确认。建议每周导出一次并按 `progress/YYYY/YYYY-MM-DD.json` 归档。

## 四个核心能力

| 需求 | 对应功能 | 位置 |
| --- | --- | --- |
| 分阶段学习计划 | 四阶段 29 周任务表，勾选打卡，进度自动保存，当前周自动高亮 | 「学习计划」 |
| 理论知识指导 | 13 模块学习引导（学习目标 / 核心知识点 / 重点 / 难点）+ 要点速览 + 学习路径 + 高频易错点，配 `docs/02-知识点精要` 精讲文档 | 「知识模块」 |
| 历年真题 | 8 套上午卷共 318 题，按年份 / 卷型 / 模块筛选，交互与刷题练习一致 | 「真题题库」 |
| 阶段测评 | 3 套阶段测评（40~45 题 / 45~50 分钟），交卷给出模块得分与达标判定 | 「阶段测评」 |
| 模拟考试 | 8 套模拟考试（75 题 / 120 分钟 / 75 分）+ 4 套下午卷（自评）+ 成绩趋势 | 「模拟考试」「成绩分析」 |

辅助：错题本（真题错题置顶重点管理 + 自编错题原流程；错因下拉、自动结论建议、三态复习标记、错因统计；工具栏可打开错题归档页、导出 CSV）、刷题练习（自选模块 / 随机 / 按模块 / 错题重做）、真题题库（按模块 / 按年份浏览，整卷或单题练习）、备考文档页（docs 下 18 篇备考 HTML 汇总入口，平台开发文档另在 `docs/平台开发/`）、成绩趋势折线图、导出备份。

刷题练习的四种模式：**自选模块**（勾选已学完的模块，题量按上午卷权重折算，20/30/40/75 四档，可理解为缩小版上午卷）、**随机 30 题**（全库随机，碎片时间保持手感）、**按模块**（单模块整刷，题序随机）、**错题重做**（待攻克错题，答对自动标记已掌握）。自选模块的勾选与档位存在 `rk_sd_practice_sel`，下次进入自动带回。

### 真题题库（2026-11-24 补全 2020—2023 + 解析结构化 + 自选练习）

与刷题练习并列的**独立模块**，入口在左侧「真题题库」。现有 `views-practice.js`、自编题库文件、`rk_sd_answers` / `rk_sd_wrong` 与 `rk_sd_practice_sel` 均未改动。

- **数据范围**：已入库 8 套上午卷共 **318 题**：2020 下 53/75、2021 上 58/75、2022 上 26/75、2022 下 62/75、2023 上 61/75、2023 下 32/75、2024 上 11/75、2024 下 15/75。**2020 上半年未举办**（人社部答复确认并入下半年），题库不设该空套卷。2021 下因公开来源题号冲突暂缓录入；2025 上/下、2026 上/下只登记来源（0 题），年份筛选显示「待补」且不可勾选。覆盖 13 个模块中的 12 个；多媒体没有题位。
- **缺口与口径**：2021 上标「单源」（CFANZ 全文），缺答案/配图共 17 题未录；2022 上标「单源」（人人文库全文），来源仅 1~30 题可见，第 31~75 无完整公开题面；2023 下标「单源」（人人文库全文），来源仅 1~32 题可见，第 33 题截断、34~75 不可见；2021 下三来源题号冲突暂缓，未入库。2024 上只收 1~7、9~12，第 8 题缺图，第 13~75 题公开来源没有可核对的题干与答案；2024 下按希赛网回忆版收题面/答案齐全的 1~8、21~30 段共 15 题（第 1、7、23 题缺图或排版残缺未录），标「回忆版」；2023 上为软考吧题面 + CSDN 逐题答案表，题面/答案不同源，标「单源」，其中第 8、52 题答案按知识点人工订正；2024 上为希赛题面 + 希赛/哔哩哔哩回忆版答案，标「回忆版」；2020/2022 标「已核对」。2020 下缺 41~47，另有 15 题依赖配图/表格/代码或 OCR 残缺；2022 下 12 题、2023 上 14 题因同类原因未录入，题号已写在各套卷卡片上。
- **2025/2026 复核（2026-11-23）**：希赛 2025 上仅给题面无答案、2025 下仅给 1~30 答案要点无题面、2026 上答案为空（需视频）且部分题缺图，均不满足「题面 + 答案可交叉核对」，维持 0 题登记。
- **题干与解析展示**：题干填空占位的题号数字已去除、仅保留横线（中文 `（1）` → `____`、英文 `______(71)` → `______`），原题号仍在题头「原题 N」显示，`O(1)` / `range(11)` 等正常记号保留。解析统一为三段结构：答案（自动取正确选项文本，不含字母）/ 解题思路 / 推导过程；来源标注「原卷解析整理」或「自编解析」。分段解析按套卷存 `assets/js/real/r-explain-*.js`，由 `RK.real.registerExplanations` 注册，`RK.real.explanationFor(q)` 查询并兜底。
- **数据结构**：`assets/js/data-real.js` 提供 `RK.real.registerPaper(meta)` / `RK.real.register(list)` / `RK.real.filterQuestions({years,paperTypes,modules})` / `RK.real.registerExplanations(map)` / `RK.real.explanationFor(q)`。套卷字段：`key / year / half / label / exam / paperType / total / included / count / absent / excluded / source / sourceLabel / answerSource / answerSourceUrl / explanationSource / verified / pending / sourceNote`；题目字段：`id / paper / no / year / paperType / kind / module / topic / stem / options[4] / answer / explanation / group / blank / source / sourceUrl / answerSource / answerSourceUrl / explanationSource / explanationUrl / verified`。题目未显式给出的来源/年份/卷型/核对状态从套卷 meta 继承，旧字段名保持兼容。
- **分类组织**：主分类复用 `RK.MODULES` 的 13 个模块 key（与知识模块、自编题库同一套命名/颜色/权重），次分类为套卷年份与卷型（`morning` / `afternoon`）。首页同时给出「按模块浏览」「按年份浏览」和「自选真题练习」。
- **自选练习**：首页勾选年份（2025/2026 为待补、禁用）、卷型（当前仅上午卷；下午案例卷待补）、模块（可全选/清空），题量档为「全部 / 20 / 30 / 50」；实时预览「匹配 N 题，本次抽 M 题」并按模块拆分明细。年份和模块至少各选 1 个。选择存 `rk_sd_real_sel`，下次进入自动带回。开始后进入 `#/real?s=1&y=…&t=…&m=…&n=…`，`n=0` 表示全部匹配题。
- **练习流程**：首页 → 自选/模块/套卷 → 练习。点击选项立即判题并按「答案 / 解题思路 / 推导过程」三段显示解析，来源行标注解析来源（自编解析会提示依据题面与知识点编写）与题面/答案出处；题头显示核对状态（已核对 / 单源 / 回忆版）。上一题/下一题、计数器、练习小结、按模块正确率、再练一遍与真题错题重做，交互与刷题练习一致。自选/按模块随机打乱，整卷保持原题号顺序。
- **数据隔离**：真题作答写 `rk_sd_real_answers`，真题错题写 `rk_sd_real_wrong`（含错因、一句话结论、复习状态），筛选条件写 `rk_sd_real_sel`；不进入 `rk_sd_answers` / `rk_sd_wrong`，不影响自编题库掌握度、模拟考试与成绩分析。答对真题错题会自动标为「已掌握」。错题本统一展示两组，但统计与备份互不混算。
- **来源**：2020/2022 下来自 `xiaomabenten/software_designer`（MIT）；2021 上来 CFANZ 编程社区；2022 上来人人文库（选项经希赛/CSDN 校订）；2023 下来人人文库（题位与 51CTO 公开卷交叉吻合）；2023 上题面来自软考吧、答案来自 CSDN；2024 上题面来自希赛、答案为希赛/哔哩哔哩回忆版，2024 下题面与答案来自希赛网回忆版；2021 下暂缓与 2025/2026 来源登记见 `docs/07`。真题原文与解析的权利归原命题、出版或整理方，本项目仅本地个人备考使用。

错题本 CSV 列顺序：`题号, 题目, 我的答案, 正确答案, 错因, 一句话结论, 模块, 考点, 错误次数, 状态, 最近错误时间`。「错因」「一句话结论」读取页面中填写的值（未填时分别导出「未归因」「未填写」）；文件带 UTF-8 BOM，Excel / WPS 直接打开不乱码。CSV 与速记表只导出自编错题，真题错题留在 `rk_sd_real_wrong` 单独管理。

### 错题本 · 真题错题重点管理（2026-11-23）

真题优先级高于自编模拟题，错题本把「真题错题 · 重点管理」置顶，自编错题原流程保持不变。

- **存储口径**：真题错题仍写 `rk_sd_real_wrong`，错因/一句话结论/复习状态随记录保存，作为 v2 备份的 `realWrong` 类别单独导出；两组错题统一展示但互不混算。
- **错因分类**：复用 `RK.CAUSES` 八类（概念混淆 / 公式记错 / 计算失误 / 审题偏差 / 知识盲区 / 术语不熟 / 时间不够 / 蒙对未掌握）；选定错因后按 `RK.CAUSE_ADVICE` 自动给出一条可执行结论建议，自由文本「一句话结论」可覆盖它。
- **分类标签**：按模块 / 年份 / 套卷 / 错因自动生成，不提供自定义标签输入；顶部按复习状态与错因筛选。
- **复习标记**：待复习 / 复习中 / 已掌握三态，可手动切换；答错回到「待复习」、答对自动「已掌握」，旧记录的 `resolved` 自动映射为三态。
- **错因统计**：按错因、模块分别计数并画条形统计；真题为单独一组并置顶，自编错题另列一组对照。
- **解析**：真题错题展开后按「答案 / 解题思路 / 推导过程」三段展示，与真题练习页一致。

## 建议的使用节奏

**每天（约 2 小时）**
1. 打开「总览」，看本周任务与今日待办；
2. 按计划执行 1 个学习块 + 1 次刷题（20 题左右）；
3. 错题当天进错题本，标注错因类型。

**每周（周末半天）**
1. 补完本周未打卡任务；
2. 做 1 次「自选模块练习」，只勾本周所学模块（题量按它们在上午卷中的权重折算）；
3. 回看错题本中本周新增的题，重做一遍。

**每阶段结束**
1. 做对应「阶段测评」，看模块得分表；
2. 正确率 < 60% 的模块回到「知识模块」重看要点，补练该模块题库全部题目（实际题量见「知识模块」页的「题库现有」一项）；
3. 达标后再进入下一阶段。

**冲刺期（W25 起）**
每周 2 套模拟考试，严格 120 分钟不查资料；考后 1 小时内完成复盘并更新「考前必看清单」。

## 数据存储

所有进度存在浏览器 `localStorage`（键前缀 `rk_sd_`），不上传、不联网。

- 换浏览器或清缓存会丢失，**建议每周在「错题本 → 数据管理 → 导出备份」保存一次 JSON（v2，含真题记录）**。
- 导出的 JSON 按 `progress/YYYY/YYYY-MM-DD.json` 归档（`progress/` 是独立 Gitee 私有仓库，不入本仓库），字段含义、采集节奏与恢复方式见 `progress/README.md`。
- 备份格式 v2：根字段 `_meta`（`format`、`version`、`mode`、`categories`、`schema` 字段说明）+ `exportedAt` + 按需包含的数据类别。完整导出含全部 8 类；选择性导出只含勾选类别，导入时未包含的类别保持本机不变。字段说明写在备份文件里，换设备也能读懂结构。
- 8 类数据：自编作答 `answers`、自编错题 `wrong`（含错因与一句话结论，即用户笔记）、成绩 `exams`、打卡 `tasks`、真题作答 `realAnswers`（`rk_sd_real_answers`）、真题错题 `realWrong`（`rk_sd_real_wrong`，含三态复习文字）、真题筛选 `realSel`（`rk_sd_real_sel`）、练习筛选 `practiceSel`（`rk_sd_practice_sel`）。`rk_sd_theme` 是界面主题，非学习数据，不进备份。
- 导入兼容旧版四字段备份（无 `_meta`，按 v1 处理）；逐类校验格式、写入后回读核对，失败回滚并提示；版本不支持或类别未知时拒绝导入。
- 归档脚本 `tools/archive-progress.js` 要求旧四字段齐全，**请用「完整导出」的文件归档**；选择性备份用于跨设备补数据，不要作为唯一快照。
- 无痕模式下数据不落盘。

## 扩展题库

在 `assets/js/bank/` 下新增文件，按现有格式注册即可：

```js
(function (RK) {
  RK.registerQuestions([{
    id: 'CS-016',                       // 全局唯一
    module: 'computer-system',          // 必须是 RK.MODULES 中的 key
    topic: '数据表示',
    difficulty: 2,                      // 1~3
    stem: '题干……',
    options: ['A 项', 'B 项', 'C 项', 'D 项'],
    answer: 0,                          // 正确项下标，从 0 开始
    explanation: '解析……',
    tags: ['计算']
  }]);
})(window.RK);
```

再在 `index.html` 里加一行 `<script src="assets/js/bank/xxx.js"></script>`，然后运行：

```bash
node tools/check-data.js        # 结构校验：id 重复、答案越界、组卷题数、计划完整性
node tools/check-coverage.js    # 覆盖校验：要点是否有题、题量是否够权重×3/×5、模拟考试重复率
node tools/check-coverage.js --strict   # 提交前检查：不达标退出码 1
node tools/check-real.js        # 真题校验：题量、模块覆盖、答案、与自编题库隔离
```

`check-data.js` 检查 id 重复、答案越界、模块覆盖、组卷题数是否够 75、计划任务完整性，输出答案位置分布（0/1/2/3 各占 25%±3 个百分点，超限只提示不阻断）与题型 / 难度分布；第 9 节校验**模块—要点—文档口径一致性**：`core.js` 别名唯一且精要文档存在、`docs/02` 每篇恰好 1 行要点锚点、57 个要点与 11 篇双向一一对应、`docs/00` 索引表逐列（别名/权重/题量/要点数/文档名）与源码一致、13 个模块均出现在某阶段 `focus` 中。

`check-coverage.js` 按 `data-syllabus.js` 的要点组统计题量，输出「无题要点」「未归类 topic」与 8 套模拟考试的两两重合率。加 `--strict` 可在题量不足、仍有要点无题或模拟考试重合率 > 40% 时返回非零退出码。

下午案例题用 `RK.registerAfternoon`，字段为 `type`（`dfd` / `uml` / `db` / `algo` / `java` / `cpp`）、`background`、`questions[{q, score, answer}]`、`tips`。

**扩展真题题库**：在 `assets/js/real/` 下新增一个套卷文件，按现有格式注册：

```js
(function (RK) {
  RK.real.registerPaper({
    key: '2023-05', year: 2023, half: '上半年', label: '2023 年上半年',
    exam: '软件设计师（中级）· 上午卷（综合知识）', paperType: 'morning',
    total: 75, count: 0, absent: '', excluded: '',
    source: '题面链接', sourceLabel: '题面来源',
    answerSource: '答案来源', answerSourceUrl: '答案链接',
    explanationSource: '解析来源', verified: 'single-source', pending: false
  });
  RK.real.register([{
    id: 'ZR-2023-05-001', paper: '2023-05', no: 1,
    year: 2023, paperType: 'morning', kind: 'choice',
    module: 'computer-system', topic: '存储系统',
    stem: '题干……', options: ['A', 'B', 'C', 'D'],
    answer: 0, explanation: '解析……', group: 1, blank: 0,
    source: '题面来源', answerSource: '答案来源',
    explanationSource: '未提供', verified: 'single-source'
  }]);
})(window.RK);
```

再在 `index.html` 的真题脚本区加一行 `<script src="assets/js/real/r-2023-05.js"></script>`，并运行 `node tools/check-real.js`。`module` 必须是 `RK.MODULES` 中的 key。真题 id 统一用 `ZR-<套卷>-<三位题号>`，不要与自编题库 id 混用。题干填空占位只写横线、不写题号数字（展示层会自动清理历史数据中的 `（数字）`），原题号由 `no` 字段保留。

多空题按现有结构拆成多条记录：同一组记录的 `stem` 与 `group` 必须一致，`group` 填总空数，`blank` 填第几空（1 起）。每条记录的 `stem` 都要保留全部横线，按从左到右顺序对应 `blank=1..group`；`options`/`answer` 只写当前 `blank` 那一问，不要混入其他空的选项。作答页会把每个横线显示为「第 N 空」并高亮当前空，选项区会声明归属；`node tools/check-real.js` 会校验横线数量、同一组的 `blank` 是否齐全且不重复。

**三段解析**：另建 `assets/js/real/r-explain-<套卷>.js`，用 `RK.real.registerExplanations({ '<题目id>': { idea, derivation, answer?, source?, selfComposed? } })` 注册。`idea` 为解题思路、`derivation` 为推导过程，`answer` 可省略（自动取正确选项文本）；`selfComposed: true` 标注为自编解析。展示层用 `RK.real.explanationFor(q)` 查询，缺条目时按旧 `explanation` 兜底。解析中不写选项字母引用（选项会乱序）。在 `index.html` 注册解析脚本并跑 `node tools/check-real.js` 校验三段齐全。

数据质量约定：`verified` 取 `crosschecked`（已核对）/ `single-source`（题面与答案不同源）/ `recalled`（回忆版）/ `pending`（待补）。只有答案速对、没有完整题面的套卷用 `pending: true` + `count: 0` 登记来源，不生成题目；题目可只给答案、解析按知识点自编并标「自编解析」，帮助理解答案来源，但题面与答案必须可核对。新增/修改套卷后同步 `docs/07` 的来源与缺口表。
