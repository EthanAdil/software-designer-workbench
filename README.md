# 软件设计师（软考中级）备考工作台

面向 **2027 年上半年 · 软件设计师** 的系统化备考项目：四阶段 29 周计划 + 13 模块知识精讲 + 377 道上午题（含 5 篇专业英语共 25 空）+ 24 道下午案例 + 3 套阶段测评 + 8 套全真模考 + 4 套下午卷。

参考了 GitHub 上主流软考项目的组织方式（`xiaomabenten/software_designer` 的资料体系、`chenguanghua/soft-exam-web` 的纯静态学习站形态），做成**零依赖、双击即用**的本地工作台。

---

## 快速开始

双击 `index.html` 即可（Chrome / Edge / Firefox 均可，无需安装任何东西、无需起服务）。

如果浏览器限制了本地文件脚本，用任意静态服务打开：

```bash
python -m http.server 8731
# 然后访问 http://localhost:8731
```

> 8731 是刻意选的冷门端口，避免和本机常驻服务（8080、8000、3000 等）撞车；若仍被占用，换任意四位数即可。

> **文档编码**：`docs/` 下的 `.md` 是源文件，`.html` 是生成物（改完 `.md` 执行 `node tools/build-docs.js` 刷新）。HTML 头部已声明 `<meta charset="utf-8">`，用浏览器打开 `.html` 不会乱码；直接打开 `.md` 时个别浏览器会按系统 GBK 猜测编码，从而显示成乱码。

## 四个核心能力

| 需求 | 对应功能 | 位置 |
| --- | --- | --- |
| 分阶段学习计划 | 四阶段 29 周任务表，勾选打卡，进度自动保存，当前周自动高亮 | 「学习计划」 |
| 理论知识指导 | 13 模块要点速览 + 学习路径 + 高频易错点，配 `docs/02-知识点精要` 精讲文档 | 「知识模块」 |
| 阶段测评 | 3 套阶段测评（40~45 题 / 45~50 分钟），交卷给出模块得分与达标判定 | 「阶段测评」 |
| 模拟考试 | 8 套全真模考（75 题 / 120 分钟 / 75 分）+ 4 套下午卷（自评）+ 成绩趋势 | 「模拟考试」「成绩分析」 |

辅助：错题本（自动收录 + 答对标记已掌握；每题可填错因与一句话结论；工具栏可打开模板、导出 CSV）、刷题练习（按模块 / 随机 / 错题重做）、备考文档页（docs 下 15 篇 HTML 汇总入口）、成绩趋势折线图、数据导出备份。

错题本 CSV 列顺序：`题号, 题目, 我的答案, 正确答案, 错因, 一句话结论, 模块, 考点, 错误次数, 状态, 最近错误时间`。「错因」「一句话结论」读取页面中填写的值（未填时分别导出「未归因」「未填写」）；文件带 UTF-8 BOM，Excel / WPS 直接打开不乱码。

## 建议的使用节奏

**每天（约 2 小时）**
1. 打开「总览」，看本周任务与今日待办；
2. 按计划执行 1 个学习块 + 1 次刷题（20 题左右）；
3. 错题当天进错题本，标注错因类型。

**每周（周末半天）**
1. 补完本周未打卡任务；
2. 做 1 次「按模块练习」，只选本周所学模块；
3. 回看错题本中本周新增的题，重做一遍。

**每阶段结束**
1. 做对应「阶段测评」，看模块得分表；
2. 正确率 < 60% 的模块回到「知识模块」重看要点，再补 15 题；
3. 达标后再进入下一阶段。

**冲刺期（W25 起）**
每周 2 套全真模考，严格 120 分钟不查资料；考后 1 小时内完成复盘并更新「考前必看清单」。

## 数据存储

所有进度存在浏览器 `localStorage`（键前缀 `rk_sd_`），不上传、不联网。

- 换浏览器或清缓存会丢失，**建议每周在「成绩分析 → 导出备份」保存一次 JSON**。
- 导出的 JSON 建议按 `progress/YYYY/YYYY-MM-DD.json` 归档并提交，字段含义、采集节奏与恢复方式见 `progress/README.md`。
- 无痕模式下数据不落盘。

## 扩展题库

在 `assets/js/bank/` 下新增文件，按现有格式注册即可：

```js
(function (RK) {
  RK.registerQuestions([{
    id: 'CS-016',                       // 全局唯一
    module: 'computer-system',          // 必须是 RK.MODULES 中的 key
    topic: '数据表示',
    difficulty: 2,                      // 1~3
    stem: '题干……',
    options: ['A 项', 'B 项', 'C 项', 'D 项'],
    answer: 0,                          // 正确项下标，从 0 开始
    explanation: '解析……',
    tags: ['计算']
  }]);
})(window.RK);
```

再在 `index.html` 里加一行 `<script src="assets/js/bank/xxx.js"></script>`，然后运行：

```bash
node tools/check-data.js        # 结构校验：id 重复、答案越界、组卷题数、计划完整性
node tools/check-coverage.js    # 覆盖校验：要点是否有题、题量是否够权重×3/×5、模考重复率
node tools/check-coverage.js --strict   # 提交前检查：不达标退出码 1
```

`check-data.js` 检查 id 重复、答案越界、模块覆盖、组卷题数是否够 75、计划任务完整性。

`check-coverage.js` 按 `data-syllabus.js` 的要点组统计题量，输出「无题要点」「未归类 topic」与 8 套模考的两两重合率。加 `--strict` 可在题量不足、仍有要点无题或模考重合率 > 40% 时返回非零退出码。

下午案例题用 `RK.registerAfternoon`，字段为 `type`（`dfd` / `uml` / `db` / `algo` / `java` / `cpp`）、`background`、`questions[{q, score, answer}]`、`tips`。

## 说明

- **题库为按考点自编的练习题，不是官方真题**。模考分数用于自查与节奏训练，不等同于真实考试预测；建议在 W27、W28 配合近年真题使用。
- 考试日期按往年规律取 **2027-05-22**，实际以准考证为准；考试结构（两科连考 240 分钟、各 75 分、45 分合格、单科不保留）依据 2026 年现行规则，若官方调整以官方为准。
- 权重（软件工程 13 题、面向对象 9 题等）为历年分布的经验值，每年有 ±1~2 题浮动。
